지뢰찾기 아레나(MineApp)는 클래식 지뢰찾기로 시작했습니다. 그런데 처음부터 대전을 붙일 생각이었고, 그러려면 **두 사람이 같은 판을 받아야** 했습니다.

보드를 통째로 주고받는 건 안 하기로 했습니다. 최고급이 40×20이라 720칸인데, 매치가 잡힐 때마다 그걸 서버에 올렸다 내리는 건 낭비였습니다. 대신 **판을 숫자 하나로 줄였습니다.**

```swift
struct SeededGenerator: RandomNumberGenerator {
    private var state: UInt64
    init(seed: UInt64) { state = (seed == 0) ? 0x9E3779B97F4A7C15 : seed }
    mutating func next() -> UInt64 { /* SplitMix64 */ }
}
```

같은 시드를 넣으면 같은 지뢰 배치가 나옵니다. 그래서 서버는 `seed` 하나만 양쪽에 던져주면 되고, 보드는 각자의 기기가 만듭니다. 이 결정이 뒤에 나올 모든 모드의 바닥이 됐습니다.

## 난이도는 네 개입니다

![난이도 선택 시트 — 초급 9×9 지뢰 10, 중급 16×16 지뢰 40, 고급 30×16 지뢰 99, 최고급 40×20 지뢰 190](/images/mineapp-solo-board/difficulty.png)

| 난이도 | 크기 | 지뢰 |
|---|---|---|
| 초급 | 9×9 | 10 |
| 중급 | 16×16 | 40 |
| 고급 | 30×16 | 99 |
| 최고급 | 40×20 | 190 |

가로가 아니라 **세로로 긴 판**입니다. 원조 지뢰찾기의 고급은 30×16 가로판인데, 그걸 폰에 그대로 올리면 칸이 손톱만 해집니다. 그래서 행과 열을 뒤집었습니다. 최고급만 가로 회전도 허용하고, 나머지는 세로로 잠급니다.

## 첫 탭에서 죽으면 게임이 아닙니다

첫 탭에 지뢰를 밟는 건 플레이어가 뭘 잘못한 게 아닙니다. 그래서 **지뢰를 처음부터 깔지 않습니다.**

새 판을 시작하면 빈 보드만 만들고 시드는 들고만 있습니다.

```swift
func startSeeded(seed: UInt64) {
    self.seed = seed
    buildEmptyGrid()        // 지뢰·오픈 없음 — 첫 클릭 때 배치
    minesPlaced = false
    state = .ready
}
```

![첫 탭 전의 빈 보드 — 남은 지뢰 040, 타이머 000](/images/mineapp-solo-board/board-empty.png)

첫 탭이 들어오면 그때 그 칸을 안전 칸으로 삼아 지뢰를 깝니다. 금지 구역은 **탭한 칸과 그 주변 8칸**입니다. 탭한 칸만 빼면 사방이 지뢰인 `8`이 나올 수 있는데, 그러면 첫 수부터 찍기가 되거든요.

```swift
var forbidden = Set<Int>()
forbidden.insert(safeR * cols + safeC)
for (dr, dc) in offsets { /* 주변 8칸도 금지 */ }

var candidates = (0..<(rows * cols)).filter { !forbidden.contains($0) }
candidates.shuffle(using: &rng)
```

주변 8칸까지 비우면 첫 탭은 거의 항상 `0`이 나오고, 연쇄 오픈이 한 번에 터지면서 판이 열립니다.

![첫 탭 직후 — 연쇄 오픈으로 가운데가 한 번에 열렸습니다](/images/mineapp-solo-board/board-first-tap.png)

**섞기가 시드 난수라는 게 중요합니다.** `candidates.shuffle(using: &rng)` 의 `rng` 가 `SeededGenerator` 라서, 같은 시드 + 같은 첫 탭이면 같은 판이 나옵니다. 시드만 같아도 첫 탭 위치가 다르면 배치가 달라지는데, 대전에서는 **안전 칸 좌표까지 서버가 정해서** 양쪽에 같이 내려보냅니다.

## 판 코드 — 시드를 사람이 읽을 수 있게

시드가 판이라면 그 시드를 남에게 줄 수 있어야 합니다. 그런데 `2516607382` 를 카톡으로 보내라고 할 수는 없었습니다.

```swift
static func makeCode(difficulty: Difficulty, seed: UInt64) -> String {
    let s = String(seed & 0xFFFF_FFFF, radix: 36, uppercase: true)
    return "\(difficulty.code)-\(s)"
}
```

난이도 글자 하나 + 시드를 36진수로 찍습니다. `I-DAMXCO` 처럼 나옵니다. 앞 글자를 보면 어느 난이도인지 알 수 있고, 되돌릴 때는 대소문자·공백·대시를 전부 무시하고 읽습니다.

![판 코드 시트 — 이 판 I-DAMXCO, 코드를 입력해 같은 판 불러오기](/images/mineapp-solo-board/board-code.png)

시드를 `& 0xFFFF_FFFF` 로 32비트만 남기는 건 코드 길이 때문입니다. 64비트를 다 쓰면 13자리가 나오는데, 그건 손으로 옮겨 적을 수 있는 길이가 아닙니다. 어차피 새 판의 시드도 `UInt32.random` 으로 뽑고 있어서 잘리는 값이 없습니다.

최고 기록은 **코드별로** 저장합니다. 그래서 「중급 최고 기록」이 아니라 「이 판의 최고 기록」이 남습니다. 같은 판을 몇 번이고 다시 풀면서 시간을 줄이는 쪽이, 매번 새 판을 받는 것보다 기록 경쟁으로는 공평했습니다.

## 죽었는데 다시 처음부터는 너무합니다

고급 이상에서 20분쯤 풀다가 마지막에 하나 잘못 눌러서 죽으면, 그때 앱을 닫습니다. 저부터 그랬습니다.

그래서 **이어하기**를 넣었습니다. 밟은 지뢰는 깃발로 바꿔 두고, 게임오버가 자동으로 드러낸 나머지 지뢰는 다시 가린 뒤 그 자리에서 계속합니다.

```swift
func continueGame() {
    guard state == .lost, !reviveExploded.isEmpty else { return }
    for idx in gameOverRevealed { /* 드러난 지뢰 다시 가리기 */ }
    for idx in reviveExploded   { /* 밟은 지뢰는 깃발로 */ }
    // 잘못 세운 깃발(지뢰가 아닌 칸)은 전부 해제한다.
    ...
    didContinue = true
}
```

여기서 하나 걸렸던 게 있습니다. 죽는 원인은 대부분 **잘못 꽂은 깃발**입니다. 숫자를 눌러 주변을 일괄로 여는데, 깃발이 엉뚱한 데 꽂혀 있으면 그 숫자가 「충족」된 걸로 보고 진짜 지뢰를 열어 버리거든요. 그 상태로 이어하기를 주면 같은 자리에서 또 죽습니다. 그래서 이어할 때 **틀린 깃발을 전부 뽑아 줍니다.** 어느 깃발이 틀렸는지는 알려주지 않고, 그냥 다 뽑습니다.

대신 **이어한 판은 기록에 안 남깁니다.** `didContinue` 가 서면 최고 기록도 랭킹도 건너뜁니다. 죽고 이어서 낸 시간이 한 번에 깬 시간과 같은 표에 올라가면 그 표는 의미가 없습니다.

## 앱을 껐다 켜도 판이 남습니다

이어하기와 헷갈리기 쉬운데, 이건 다른 이야기입니다. 최고급 한 판이 20분인데 중간에 전화가 오면 판이 날아갔습니다.

백그라운드로 갈 때 칸 상태를 통째로 저장합니다.

```swift
struct SoloSnapshot: Codable {
    struct CellData: Codable {
        var m: Bool   // 지뢰
        var r: Bool   // 열림
        var f: Bool   // 깃발
        var x: Bool   // 터짐
        var a: Int    // 주변 지뢰 수
        var g: Bool?  // 황금지뢰
    }
    ...
}
```

**보드는 시드로 다시 만들 수 있는데 왜 칸을 다 담느냐**를 한참 고민했습니다. 시드만 저장하면 배치는 복원되지만 「어디까지 열었고 깃발을 어디에 꽂았는지」는 안 남습니다. 그걸 따로 저장할 거면 어차피 칸당 몇 비트가 필요하고, 그럴 바에는 통째로 담는 게 코드가 단순했습니다. 최고급 720칸을 다 담아도 수 KB라 `UserDefaults` 로 충분합니다.

키 이름이 `m` `r` `f` `x` `a` `g` 로 한 글자인 건 그 JSON이 칸 수만큼 반복되기 때문입니다.

구버전 스냅샷 때문에 `g`(황금지뢰)만 옵셔널입니다. 나중에 추가된 필드라 옛 저장본에는 없고, 없으면 `false` 로 봅니다. 같은 이유로 「아이템을 썼는지」 필드는 **없으면 `true`(썼다)로** 취급합니다 — 판단이 안 서면 칭호를 안 주는 쪽으로 기울여야 오지급이 안 납니다.

## 남은 것

**보드를 값 하나로 만들 수 있으면 그 뒤가 전부 쉬워집니다.** 이 앱의 대전·협동·보물찾기가 전부 「같은 시드를 양쪽에 던진다」로 시작합니다. 처음에 보드를 직렬화해서 주고받는 쪽으로 갔다면 모드를 추가할 때마다 그 포맷을 늘리고 있었을 겁니다.

**진행 상태는 결정적으로 만들 수 없습니다.** 보드는 시드로 되살아나지만 「내가 어디까지 풀었는가」는 아닙니다. 재현 가능한 것과 저장해야 하는 것을 갈라 두면, 무엇을 아끼고 무엇을 통째로 담을지가 자동으로 정해집니다.
