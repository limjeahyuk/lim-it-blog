> GIT 이란  
> 분산 버전 관리 시스템 (DVCS) 중 하나로, 버전 관리 시스템의 한 종류입니다.  
> 코드 변경 이력을 스냅샷처럼 저장하고, 브랜치 / 머지를 빠르고 가볍게 할 수 있는 도구.

분산 버전 관리 시스템

\- 하나의 중앙 서버가 존재하지만,  
여러 클라이언트들은 각자의 컴퓨터 저장소에 전체 사본을 가지고 작업을 하는 방식입니다.

* * *

#### git의 장점

-   로컬 저장소
    -   중앙 서버 없이도 모든 개발자가 전체 코드의 복사본을 가지므로, 네트워크 연결 없이도 작업이 가능합니다.
    -   백업 및 복구가 용이합니다.
-   협업
    -   팀원 간의 코드 공유, 변경 이력 추적이 매우 쉽습니다.
    -   코드 리뷰나 코드를 이해하고 통합하는 능력이 향상됩니다.
-   효율적인 브랜칭 및 병합
    -   브랜치를 생성하고 병합하는 과정이 매우 가볍고 빠릅니다.
    -   메인 코드에 영향을 주지 않고 독립적으로 진행할 수 있어서 안전하고 유연한 개발이 가능합니다.
-   데이터 저장 방식이 매우 효율적이어서 빠른 속도를 자랑합니다.

* * *

#### Git을 대체할 도구

**SVN**

특징

-   중앙집중식 버전 관리 시스템
-   중앙 서버가 관리하고 클라이언트는 필요한 버전만 체크아웃합니다.

장점

-   중앙 서버가 관리하기에 git에 비해 상대적으로 간단한 사용법을 가지고 있고 사용자 또한 쉽게 익힐 수 있습니다.
-   중앙 서버가 있기에 데이터의 안정성을 보장할 수 있습니다.

단점

-   중앙 서버를 거쳐야하기에 서버와의 연결이 필요합니다.
-   파일 단위로 변경 이력을 관리하기에 변경 이력이 많은 경우 성능 저하가 발생합니다.

* * *

GIT이 표준이 된 이유

-   **리눅스 커널 프로젝트를 위한 설계 → 규모·성능 검증**
    -   리눅스 커널 개발은  
        기여자 많고 브랜치·패치가 엄청나게 많고 분산 개발 그 자체  
        이 환경에서 git이 잘 버티고 성장.
-   **오픈소스 + 자유로운 도입**
    -   누구나 무료로 쓸 수 있고, 수정/확장도 가능.
    -   회사, 오픈소스, 개인 프로젝트에서 제약 없이 도입하기 쉬움.
-   **브랜치/머지에 최적화된 모델**
    -   분산 + 스냅샷 + 브랜치 포인터 구조 덕분에:
        -   실험적인 개발 스타일에 아주 잘 맞음.
        -   GitHub Flow, GitFlow 등 **브랜치 전략 문화**가 함께 발전.
-   **GitHub / GitLab 등 호스팅 플랫폼의 대성공**
    -   GitHub가 사실상 “오픈소스 SNS”가 되면서:
        -   전 세계 오픈소스가 git을 기준으로 모이기 시작.
    -   GitHub/GitLab/Bitbucket의 UI/PR/CI/CD 생태계가 git 위에 완전히 얹혀버림.
-   **도구, 튜토리얼, 커뮤니티가 git 중심으로 형성**
    -   개발 강의, 유튜브, 블로그, 책 등에서 git을 기본 전제로 깔고 설명.
    -   IDE, 클라우드, CI/CD, 코드리뷰 툴 등 거의 전부 git 통합을 제공.
