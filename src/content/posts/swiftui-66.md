#### @State

설명 먼저 하자면

-   state로 선언된 property들의 저장소를 관리합니다.
-   state Value 값이 변경되면 View는 해당 value의 appearance를 무효화하고 다시 body값을 계산.
    -   쉽게 말해서 **state로 지정해주는 값이 변경된다면 View를 새롭게 업데이트합니다.**
-   State 변수값이 변경되면 View를 새롭게 렌더링 해주기 때문에 항상 최신의 값을 가지게 됩니다.
-   **State는 현재 뷰 UI의 특정 상태를 저장하기 위해 만들어진 것이므로 private로 지정해줘야 합니다.**
    -   private이기에 다른 뷰에서는 값 재설정이 불가능합니다.

이걸 찾아보고 공부하면서 React의 State와 비슷하다는 생각을 많이 했습니다.  
React를 모르시는 분들은 죄송합니다.

주로 변경이 되는 값 + 변경되는 값에 의해 view가 업데이트 돼야 할 때...  
사용을 하는 것 같습니다.

![](/images/swiftui-66/3.png)

State를 사용하는 location과 lKey를 중점으로 보면 됩니다.

기본적으로 button 클릭을 할 때마다 @State lKey가 변경이 됩니다.  
그에 맞춰서 강북구 > 안양 > 제주도 > 유도 이런 식으로 View가 업데이트가 되고 있습니다.

하지만 lkey를 다른 뷰에서 접근하려고 하면 오류가 나게 됩니다.  
이유는 간단하게 private이기 때문에!! 

한 View에서만 상태를 변경하고 그에 맞춰서 변경될 때마다 View를 업데이트해주게 됩니다.

흠.. 근데 저는 이 상태를 다른 View에서도 접근을 하고 싶은 걸요..??

#### @Biniding

설명을 먼저 하도록 하겠습니다.

@State와 비슷.. 아니하는 짓은 거의 동일하다고 보는 게 맞을 것 같습니다.  
@Biniding 또한 State로 연결을 해줘야 하기 때문입니다.

가장 큰 차이점이라고 하면 다른 View에서도 그 변수를 접근할 수 있으며 변경이 가능합니다.  
그러면 State와 동일하게 변경될 때 view를 업데이트시켜주게 됩니다.

외부에서 접근을 하기 위해 사용하는 것이기 때문에 private를 사용하지 않습니다.

사용 시에는 $를 사용하는 데 그 부분은 코드를 보면 알 수 있습니다.

![](/images/swiftui-66/4.png)

최상위 뷰 ContentView의 자식 뷰 ChildrenView 둘 다 동일하게 btnCount라는 변수가 있습니다.  
최상위 뷰에는 @State / 자식 뷰에는 @Biniding으로 되어 있습니다.

button이 클릭될 때마다 1씩 증가하는 것은 자식뷰에서 해주고 있으며 화면에 띄우는 작업은 최상위 뷰에서 하고 있습니다.  
이렇게 다른 뷰에서 접근을 해서 변경을 하고 변경됨에 맞춰서 view를 업데이트를 해줄 때 Biniding을 사용하게 됩니다.
