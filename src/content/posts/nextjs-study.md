## Next.js

> 요즘 AI를 이용해서 여러 웹페이지를 마구마구 만들어보다가..
>
> 문득, 좋다해서 쓰고 있긴 한데 뭐가 그리 좋은 거지? 왜 좋지? 생각이 들었습니다.

### NextJS - SEO

Next.js가 SEO에 강력한 이유는 검색 엔진 봇이 자바스크립트를 해석할 필요 없이,

서버에서 이미 데이터가 모두 채워진 완성된 HTML 문서를 즉시 수집할 수 있기 때문입니다.

- **사전 렌더링 (SSR 및 SSG)**
  - 일반적인 React 기반의 순수 CSR(클라이언트 사이드 렌더링) 방식은 초기에 텅 빈 HTML(`<div id="root"></div>`)만 제공하여 봇이 자바스크립트를 실행할 때까지 기다려야 합니다.
  - 제한된 시간을 가진 봇은 이 과정을 건너뛰는 경우가 많아 정보 누락이 발생합니다.
  - Next.js는 서버 단(SSR)이나 빌드 시점(SSG)에 완전한 텍스트 구조를 만들어 전달하므로 크롤러가 100% 데이터를 읽어갑니다.
- **코어 웹 바이탈 최적화 (**`next/image`**)**
  - 구글은 페이지 로딩 속도를 랭킹에 직접 반영합니다.
  - Next.js에 내장된 이미지 컴포넌트를 사용하면 사용자 기기에 맞춰 이미지를 리사이징하고,
  
    용량이 적은 WebP나 AVIF 포맷으로 자동 변환하며,
  
    화면에 보이는 순서대로 지연 로딩을 적용해 가장 큰 콘텐츠의 렌더링 시간(LCP)을 대폭 단축합니다.
- **시각적 안정성(CLS) 확보**
  - 글꼴 로딩이나 이미지가 뒤늦게 뜨면서 화면 구조가 덜컹거리는 현상을 검색 엔진은 큰 감점 요인으로 봅니다.
  - Next.js는 `next/font`를 통한 폰트 최적화와 이미지 사전 영역 확보를 통해 렌더링 안정성을 보장합니다.
- **동적 메타데이터 주입**
  - 블로그 게시글이나 상품 페이지처럼 내용이 매번 바뀌는 동적 라우팅 환경에서도,
  
    서버 단에서 각 페이지 고유의 `<title>`, 메타 디스크립션, Open Graph 태그를 즉시 생성해 `<head>` 영역에 주입할 수 있습니다.
- **자바스크립트 번들 경량화**
  - 최신 App Router의 서버 컴포넌트를 활용하면 무거운 로직을 서버에서만 처리하고 브라우저로는 결과물만 보냅니다.
  
    기기가 다운로드하고 파싱해야 할 코드 용량이 줄어들어 모바일 크롤링 환경에서의 반응 속도가 비약적으로 상승합니다.

### Nextjs - AEO GEO

Next.js의 서버 렌더링(SSR/SSG) 아키텍처는 자바스크립트 실행 능력이 없거나 제한된 음성 비서 및 생성형 AI 크롤러에게 완성된 데이터를 즉시 제공하므로 AEO와 GEO 환경에서도 강력한 이점을 가집니다.

#### AEO (답변 엔진 최적화) 측면의 강점

- **동적 JSON-LD 즉시 주입**
  - AEO의 핵심은 검색 엔진이 페이지의 질문-답변 구조를 정확히 인식하는 것입니다.
  - Next.js는 클라이언트에서 스크립트가 로드되기를 기다릴 필요 없이, 페이지 요청 즉시 서버 단에서 FAQ나 How-to 스키마 마크업을 `<head>` 영역에 완벽하게 삽입하여 답변 엔진의 스니펫 채택률을 높입니다.
- **깔끔한 DOM 구조 제공**
  - 서버 컴포넌트를 활용하면 무거운 클라이언트 스크립트를 배제하고 순수한 HTML 시맨틱 태그(`<article>`, `<section>`) 중심으로 문서를 구성할 수 있습니다.
  - 구글 어시스턴트나 시리 같은 음성 비서 파서가 본문 내 핵심 정답 텍스트만 오류 없이 발췌하기 좋은 환경이 됩니다.

#### GEO (생성형 엔진 최적화) 측면의 강점

- **AI 봇의 자바스크립트 미실행 한계 극복**
  - ChatGPT나 퍼플렉시티 같은 생성형 AI 크롤러들은 응답 속도와 리소스 절약을 위해 브라우저를 띄우지 않고 원시 HTML만 읽고 떠나는 경우가 많습니다.
  - CSR 환경에서는 이 봇들이 빈 화면만 보고 나가지만, Next.js는 이미 텍스트가 모두 채워진 문서를 반환하여 AI 엔진의 정보 누락을 원천 차단합니다.
- **미들웨어를 통한 AI 전용 라우팅**
  - Next.js의 Edge Middleware를 활용하면 접속자의 `User-Agent`를 즉각적으로 분석할 수 있습니다.
  - 접근하는 대상이 AI 크롤러라면 렌더링을 방해하는 팝업이나 무거운 UI 요소들을 서버 단에서 제거하고, AI가 정보 문맥을 파악하고 각주로 인용하기 쉬운 텍스트 중심의 원시 데이터로 우회시키는 고도화된 대응이 가능합니다.
- **초고속 응답(TTFB) 보장**
  - 생성형 AI는 사용자에게 실시간으로 답변을 만들어내기 위해 타겟 웹사이트의 데이터를 매우 빠른 시간 안에 긁어와야 합니다.
  - Next.js의 정적 렌더링과 캐싱 기능은 응답 지연에 따른 AI 크롤러의 타임아웃 이탈을 방지합니다.

### 다른 것 들 과 다른 점

> 일반적인 React(CSR)와 Next.js(SSR/SSG)의 가장 큰 차이는 화면을 그리는 주체와 데이터가 채워진 HTML이 도착하는 시점에 있습니다.

#### **일반 React의 구동 방식 (클라이언트 사이드 렌더링, CSR)**

1. 사용자가 접속하면 서버는 텅 빈 HTML 껍데기(`<div id="root"></div>`)만 보냅니다.
2. 브라우저(또는 봇)가 전체 자바스크립트(JS) 번들을 다운로드합니다.
3. 브라우저가 JS를 실행하여 백엔드에서 데이터를 요청하고 받아옵니다.
4. 데이터가 도착하면 비로소 브라우저가 화면에 텍스트와 이미지를 그립니다.

#### **Next.js의 구동 방식 (사전 렌더링, SSR/SSG)**

1. 사용자가 접속하면, 렌더링 서버가 미리 데이터를 불러와 HTML 안에 끼워 넣습니다.
2. 내용이 100% 채워진 '완성된 HTML 문서'를 브라우저(또는 봇)에 즉시 보냅니다.
3. 접속자는 JS 다운로드를 기다릴 필요 없이 즉시 화면과 텍스트를 봅니다.
4. 백그라운드에서 JS가 뒤늦게 연결되어 버튼 클릭 등의 동적 기능을 활성화(Hydration)합니다.

#### **Q. 왜 크롤러에게 Next.js가 압도적으로 유리한가요?**

구글봇, ChatGPT 크롤러, 퍼플렉시티 봇 등은 수많은 웹사이트를 빠르게 훑어야 하므로 브라우저처럼 무거운 자바스크립트 엔진을 매번 켜서 기다려주지 않습니다.

일반 React 환경에서는 봇이 접속했을 때 텅 빈 화면만 보이기 때문에 "이 페이지는 내용이 없구나" 하고 나가버리거나, JS 처리를 후순위로 미뤄 검색 노출이 수 주일씩 지연됩니다.

반면 Next.js는 봇이 접속하자마자 자바스크립트 실행 없이도 완벽히 조립된 텍스트와 링크, 메타 태그를 읽어갈 수 있게 떠먹여 주므로 수집 누락이 원천 차단됩니다.


| **비교 항목**         | **일반 React (CSR)**      | **Next.js (SSR / SSG)**      |
| ----------------- | ----------------------- | ---------------------------- |
| **초기 수신 데이터**     | 텅 빈 껍데기 HTML            | 데이터가 완성된 HTML                |
| **첫 화면 표시 (FCP)** | 느림 (JS 실행 및 API 통신 대기)  | 매우 빠름 (즉각적 렌더링)              |
| **봇의 데이터 수집**     | 불완전함 (JS 미실행 시 데이터 증발)  | 완벽함 (JS 없이도 텍스트 100% 파싱)     |
| **서버 역할**         | 정적 파일(JS, 빈 HTML) 단순 제공 | 접속 시점(또는 빌드 시점)에 HTML 렌더링 조립 |
