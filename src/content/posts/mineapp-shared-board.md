[스피드 레이스](/posts/mineapp-speed-race)는 같은 시드로 만든 각자의 보드를 각자 풉니다.

상대가 어디를 열었는지는 안 보이고, 진행바 숫자만 보입니다.

그런데 만들고 나니 아쉬웠습니다. 상대가 옆에 있다는 느낌이 진행바 하나뿐이었습니다.

그래서 보드를 하나만 두고 둘이 같이 쓰면 어떻게 되는지 해봤습니다.

거기서 규칙이 두 개 나왔습니다.

- 지뢰 대결 — 지뢰에 먼저 깃발을 꽂는 사람이 그 지뢰를 가져갑니다. 더 많이 가져간 쪽이 이깁니다.
- 합동 — 둘이 같이 한 판을 풉니다. 누구든 지뢰를 밟으면 함께 집니다.

같은 `shared` 스위치를 켜고 시작하는데 끝나는 조건이 다릅니다.

그 하나 때문에 코드가 여기저기서 갈라졌습니다.

## 깃발에 색상을 추가했습니다

솔로에서 깃발은 그냥 표시입니다.

공유 보드에서는 누가 꽂았는지가 곧 점수라서, 칸에 색상 구분을 넣었습니다.

```swift
enum FlagOwner { case me, opponent }

struct Cell: Identifiable {
    var isFlagged = false
    var flagOwner: FlagOwner?   // 공유 보드에서 이 깃발을 꽂은 사람
    ...
}
```

![공유 보드 — 상대(주황) 깃발이 여럿, 내(파랑) 깃발 하나. 상단에 나 3% 1점 / 클리어봇 40% 16점](/images/mineapp-shared-board/duel-flags.png)

파란 깃발이 제 것, 주황이 상대 것입니다.

상대가 어디를 열고 어디에 꽂았는지가 판에 그대로 보입니다.

스피드에서 진행바 하나로 뭉뚱그려지던 정보가 여기서는 위치까지 다 드러납니다.

깃발 토글 하나에 규칙 두 개가 같이 들어 있습니다.

```swift
switch grid[r][c].flagOwner {
case .opponent:
    if rule == .coop {
        grid[r][c].isFlagged = false         // 합동: 파트너 깃발도 함께 정리 가능
        grid[r][c].flagOwner = nil
        onPushFlag?(idx, false)
    }
    return                                   // 지뢰 대결: 상대가 찜한 칸 — 손대지 못함
case .me:   ...
case .none: ...
}
```

지뢰 대결에서 상대 깃발은 못 건드립니다.

뽑을 수 있으면 점수가 뒤집히고, 그러면 마지막에 뽑는 사람이 이기는 게임이 됩니다.

반대로 합동에서는 파트너 깃발도 뺄 수 있게 열어 뒀습니다.

협력인데 파트너가 잘못 꽂은 깃발을 못 치우면 그 자리가 영영 막힙니다.

## 지뢰를 밟아도 죽지 않습니다

지뢰 대결에서 밟아 죽으면 판이 거기서 끝납니다.

그러면 남은 지뢰를 두고 겨루는 게임이 성립하지 않습니다.

그래서 죽지 않습니다.

대신 밟은 지뢰는 `exploded` 로 드러난 채 남고, 누구의 점수도 아닌 상태로 사라집니다.

지뢰를 하나 날린 셈이라 그 자체가 손해입니다.

```swift
/// 해소된 지뢰 수(누군가 차지 + 실수로 열린 지뢰). 전부 해소되면 보드 종료.
private var resolvedMines: Int {
    grid.reduce(0) { $0 + $1.lazy.filter { $0.isMine && ($0.isFlagged || $0.exploded) }.count }
}
```

여기가 이 모드에서 제일 다른 지점입니다.

다른 모드는 안전 칸을 다 열면 끝납니다. 지뢰 대결만 지뢰가 다 없어지면 끝납니다.

안전 칸이 아무리 남아 있어도 지뢰가 전부 임자를 찾으면 그 판은 더 볼 게 없습니다.

점수는 이렇게 셉니다.

```swift
var myDuelScore: Int { myMineFlags - myWrongFlags }
```

가져간 지뢰에서 잘못 꽂은 깃발을 뺍니다.

오답에 벌점이 없으면 아무 데나 다 꽂는 게 최적해가 되어 버립니다.

## 터진 지뢰 때문에 주변 일괄 열기가 안 됐습니다

숫자 칸을 눌러 주변을 한꺼번에 여는 기능이 있습니다.

주변의 확정된 지뢰 수가 숫자와 같을 때만 열립니다.

지뢰 대결에 붙이고 나서 이게 어느 순간부터 아예 안 먹는 일이 생겼습니다.

확정 지뢰를 깃발 수로만 세고 있었기 때문입니다.

밟아서 터진 지뢰는 깃발이 아닙니다. 그래서 한 번 터지면 그 주변 숫자들은 영원히 깃발이 모자란 상태가 됩니다.

```swift
// 확정된 지뢰 = 깃발 + 이미 터진 지뢰.
var accounted = 0
for (dr, dc) in offsets {
    ...
    if grid[nr][nc].isFlagged || grid[nr][nc].exploded { accounted += 1 }
}
guard accounted == cell.adjacent else { return }
```

터진 지뢰도 지뢰가 드러난 자리라는 점에서 깃발과 같습니다.

그걸 같이 세는 한 줄로 끝났습니다.

여기서 하나 더 나왔습니다.

주변 일괄 열기를 눌렀는데 지뢰가 터졌다면, 그 숫자 주변에 내가 잘못 꽂은 깃발이 있다는 뜻입니다.

그래서 그때는 주변의 내 깃발을 전부 떼어 다시 꽂게 합니다.

```swift
private func clearMyFlagsAround(_ r: Int, _ c: Int) {
    for (dr, dc) in offsets {
        ...
        guard grid[nr][nc].isFlagged, grid[nr][nc].flagOwner != .opponent else { continue }
        grid[nr][nc].isFlagged = false
        ...
    }
}
```

맞게 꽂은 깃발까지 같이 뗍니다.

틀린 것만 골라서 떼면 남아 있는 게 정답이라는 정보가 공짜로 새어 나갑니다.

상대 깃발은 상대 점수라서 손대지 않습니다.

## 내 깃발은 서버 값으로 덮지 않습니다

서버 상태가 내려오면 내 보드에 병합합니다.

이때 내 깃발은 그대로 두고 상대 것만 반영합니다.

```swift
func applySharedState(_ s: SharedBoardState) {
    guard shared else { return }
    for idx in s.revealed { reveal(index: idx, asMine: false) }
    for idx in s.exploded { reveal(index: idx, asMine: true) }

    let opp = Set(s.oppFlags)
    // 상대 깃발·열림만 병합. 내 깃발은 로컬이 우선(낙관적).
    ...
}
```

깃발을 꽂자마자 서버 응답이 올 때까지 깜빡이면 손맛이 무너집니다.

그래서 내 조작은 즉시 화면에 반영하고, 서버에서 오는 건 상대 것만 받습니다.

공유 보드는 지연이 바로 티가 나서, Firestore 대신 Realtime Database로 주고받습니다.

## 합동은 승패를 상대에게 물어보면 안 됐습니다

합동을 붙이면서 제일 오래 잡은 버그입니다.

스피드와 지뢰 대결은 상대가 끝냈다는 신호가 오면 그걸로 결과를 냅니다.

그 코드를 그대로 두고 합동을 켰더니, 파트너가 보드를 끝내는 순간 제가 졌습니다.

같이 이기는 게임인데 말이죠.

```swift
private func handleOpponent(_ status: OpponentStatus) {
    opponent = status
    guard flow == .racing, result == nil else { return }
    // 합동: 승패는 공유 보드로 직접 판정한다.
    if game.rule == .coop { return }
    ...
}
```

합동은 상대가 끝냈다는 신호를 아예 안 봅니다.

파트너가 마지막 칸을 열면 그 칸들이 공유 보드로 넘어오고, 제 쪽 승리 판정이 제 보드를 보고 함께 이깁니다.

지뢰를 밟았으면 그 `exploded` 가 넘어와서 함께 집니다.

신호를 해석할 게 아니라 보드가 이미 답을 들고 있었습니다.

같은 이유로 이탈 처리도 갈라집니다.

대전에서 상대가 나가면 부전승인데, 합동에서 파트너가 나가면 부전승이 아닙니다.

둘이 풀어야 끝나는 판이라 그냥 그 판이 끝난 것입니다.

```swift
finish(game.rule == .coop ? .lose : .win)
```

## 합동은 고급·최고급에서만 됩니다

```swift
var allowedDifficulties: [Difficulty] {
    self == .coop ? [.expert, .ultimate] : Difficulty.allCases
}
```

초급 9×9를 둘이 나눠 풀면 30초도 안 걸립니다.

서로 어디를 하고 있는지 볼 겨를도 없이 끝나서, 같이 한 느낌이 안 났습니다.

판이 넓어야 너는 왼쪽 나는 오른쪽이 생깁니다.

난이도를 잠근 게 아니라 모드가 성립하는 최소 크기를 정한 것에 가깝습니다.

## 봇은 진짜로 판을 풉니다

스피드에서는 봇이 완주 시각만 정해놓고 진행바를 채웠습니다.

공유 보드에서는 그게 안 됩니다. 봇이 어느 지뢰를 가져갔는지가 화면에 그려져야 합니다.

그래서 봇 전용으로 `GameModel` 을 하나 더 띄우고, 같은 시드로 같은 보드를 깔고, 봇이 거기서 실제로 플레이하게 했습니다.

봇이 연 칸과 꽂은 깃발이 제 화면에 상대 색으로 나타나고, 제 조작은 봇의 보드로 들어갑니다.

봇의 추론은 사람이 하는 것과 같은 두 줄입니다.

```swift
if cell.adjacent == known {
    hidden.forEach { safe.insert($0) }               // 숫자 충족 → 나머지는 안전
} else if cell.adjacent - known == hidden.count {
    hidden.forEach { mines.insert($0) }              // 남은 닫힌 칸이 전부 지뢰
}
```

세게 만드는 건 쉬웠는데, 이길 수 없는 상대는 재미가 없었습니다.

손댄 곳이 두 군데입니다.

하나는 확정 지뢰를 봐도 매번 가져가지 않는 것입니다.

확률을 두고, 나머지 턴에는 숫자를 더 엽니다.

전부 다 가져가 버리는 봇은 사람이 손쓸 틈이 없습니다.

다른 하나는 속도입니다.

```swift
/// 초반은 빠르게(≈1.0배), 후반으로 갈수록 느려진다(최대 ≈2.3배).
private static func paceMultiplier(_ progress: Double) -> Double {
    let p = min(1, max(0, progress))
    return 1.0 + 1.3 * pow(p, 1.6)
}
```

사람은 후반에 판단이 어려워져서 자연히 느려집니다.

봇만 처음부터 끝까지 일정하게 빠르면, 초반에는 비슷하다가 후반에 일방적으로 벌어집니다.

그래서 곡선을 줘서 초반 속도감은 두고 후반만 크게 늦췄습니다.

합동 봇은 반대로 갔습니다. 확정된 것만 하고 추측은 절대 안 합니다.

```swift
/// 합동 봇 한 수 — '확정된' 안전 칸만 연다. (…)
/// 추측은 하지 않는다(추측이 빗나가면 둘 다 패배하므로). 막히면 사람이 결정할 때까지 기다린다.
```

추측이 빗나가면 사람도 같이 집니다.

파트너가 찍어서 판을 날리는 건 어떤 난이도 조절보다 나쁩니다.

그래서 막히면 아무것도 안 하고 기다립니다. 위험한 수는 사람이 정하게 뒀습니다.

## 정리

모드가 갈리는 진짜 지점은 어떻게 이기는지가 아니라 언제 끝나는지였습니다.

지뢰 대결만 종료 조건이 지뢰 쪽에 붙어 있고, 그 하나 때문에 깃발과 일괄 열기가 전부 갈라졌습니다.

새 규칙을 넣을 때 승리 조건부터 적는 습관이 있었는데, 종료 조건을 먼저 적는 편이 나았습니다.

상태를 신호로 주고받을지, 보드에서 다시 읽을지 정해야 합니다.

합동 버그는 상대가 이겼다는 신호를 해석하다 난 것이고, 고친 방법은 신호를 안 보고 공유된 보드를 보는 것이었습니다.

같은 진실이 두 군데 있으면 언젠가 갈라집니다.
