### **\- div 수프**

우리는 이제 루트 jsx 요소는 하나만 있어야한다는 것을 잘 알고 있습니다.

![](/images/react-41/1.png)

위 처럼 오류가 나는 이유는 우리는 잘 알고 있습니다. jsx 요소는 한개만 있어야합니다.  
jsx 가 리액트 createElement 호출로 변환 되면서  
자바스크립트의 한계로 인해 여러가지는 return 할 수 없습니다.

이 문제를 해결 하는 법 또한 우리는 잘 알고 있습니다.

![](/images/react-41/2.png)

이런 식으로 <div></div> 태그로 묶어 주는 것입니다.

그런데 만약 가정을 하나 해보겠습니다.  
어마어마하게 많은 컴포넌트를 만들고 그 모든 컴포넌트가 div로 묶였다면?

![](/images/react-41/3.png)

이런식으로 불필요한 div 태그가 실제 DOM으로 렌더링 될 것입니다.  
당장은 아무 문제 없기 때문에 이것이 뭐가 문제인가? 싶을 수 있습니다.

하지만 대규모 프로젝트에서는 div 하나로 인해 css 스타일링을 깨트릴 수도 있으며  
스타일링에 지장을 주지 않더라도 렌더링 속도가 느려질 것입니다.

### **\- 프래그먼트 ( Fragment )**

위에서 설명한 div 수프를 해결하기 위해서는 한번씩 봤을 수도 있는 <> </> 빈태그를 사용할 수도 있습니다.

![](/images/react-41/4.png)

Q. 빈 태그를 사용하면 괜찮지 않나요?

A. 사용해도 상관은 없지만 사용하는 순간 유효한 html 이 아니게 되며  
프로젝트 설정을 해줘야합니다. > 워크플로를 빌드 해줘야합니다.

빈 태그도 좀 애매합니다... 이런 문제를 react는 해결하기 위해 컴포넌트를 제공합니다.

바로 **프래그먼트 컴포넌트** 입니다.

![](/images/react-41/5.png)

사용법은 어떤 것보다 쉽고 간단합니다.

react에서 제공하기 때문에  
**import React from 'react';**  
를 해줬다면

<React.Fragment> </React.Fragment> 로 묶어주면 사용법 끝입니다!

![](/images/react-41/6.png)

위 사진 처럼 div를 사용하면 최종 페이지에 div 태그가 있지만  
React.Fragment를 사용하면 불필요한 div태그는 사라집니다.  
훨씬 깔끔한 것을 볼 수 있습니다.

리액트 포털은 Modal에서 많이 사용 됩니다.

우리가 사용한 Modal은

![](/images/react-41/7.png)

입력창에 아무것도 안 쓰고 버튼을 눌렀을 때 뜨는 창입니다.

실제 DOM을 살펴보면

![](/images/react-41/8.png)

이것이 뭐가 문제인가? 잘 작동되기만 하기만 하는 구만! 이라고 생각할 수 있습니다.

하지만 Modal은 기본적으로 overlay입니다.  
전체 페이지에 대한 overlay로 모든 것의 위에 있어야합니다.  
하지만 다른 코드안에 중첩 되어있으면 코드를 해석하는 사람 입장에서

![](/images/react-41/10.png)

![](/images/react-41/11.png)

**※ 여기서 잠깐 ※**

**리액트는 리액트에서 사용하는 모든 기능(state관리, 애드온, 등등 ) 이 있는 라이브러리 입니다.**

따라서 **react-dom은 브라우저에 대한 리액트용 어댑터라고 생각하면 편합니다.**

그리고 그곳으로 코드를 포탈시키려고 하고 있습니다.

### **\- ref**

**reference ( 참조 )** 

ref는 참조를 뜻합니다. 가장 기본적인 기능은

**다른 DOM요소에 접근해서 그것들로 작업 할 수 있게 해주는 것입니다.**

![](/images/react-41/15.png)

여기 입력창이 있습니다.

우리는 입력창의 값을 state로 관리했습니다.  
사용자가 입력창에 한글자 한글자 키를 누를때마다 state가 업데이트 됩니다.

키를 누를 때마다 사용자로부터 얻은 값을 업데이트 하고  
그 값을 state에 저장하고  
그 state를 다시 입력창에 올려줍니다.  
그리고 종종 그 state를 사용하여 데이터가 필요한 곳으로 보내주기도 합니다.

우리가 항상 쓰던 state이지만 글로 적어보니까  
고작 입력창 하나 입력하는 건데 매우 복잡하다는 생각이 듭니다.  
또한 폼을 제출할 때만 필요한데 키를 입력할 때마다 업데이트를 하는 건 좀 과하다는 생각도 듭니다.

절대 state를 쓰는 게 잘못 되었다는 것이 아닙니다.  
이렇게 관리하는 것도 모두 장단점이 존재하며 틀린 방법은 아닙니다.

하지만 ref라는 다른 방법을 알려드리려고 합니다.

![](/images/react-41/16.png)

**Ref는 state와 동일하게 함수형 컴포넌트 안에서 useRef를 호출해줍니다.**  
첫번째 input과 연결하기 위해서 nameInputRef라고 이름을 만들었습니다.  
마찬가지로 두번째 input과 연결하기 위해 ageInputRef라고 만들었습니다.

![](/images/react-41/17.png)

input 안에 ref라는 프롭을 추가 해줍니다.  
ref는 key프롭과 마찬가지로 내장 프롭입니다.  
이말은 즉슨 어떤 HTML 요소에도 추가할 수 있다는 것입니다.

첫번째 input 에 ref = { nameInputRef }로 연결을 해줬습니다.  
nameInputRef는 ref를 저장하는 상수일 뿐입니다.

![](/images/react-41/18.png)

콘솔을 찍어보면

![](/images/react-41/19.png)

이런 식으로 나오게 됩니다.

ref에서 중요한 점은 생성되는 **ref 값은 항상 객체입니다.**  
항상 current 프롭을 가지고 있으며  
current 프롭은 ref가 연결된 것의 실제 값을 갖습니다.

**current 프롭에 저장된 값은 실제 DOM 노드입니다.**  
**따라서 조작하거나 여러가지 작업을 할 수는 있지만...**  
**최대한 하지 않는 것을 추천드립니다.**

DOM은 리액트에 의해서만 조작되어야하기 때문입니다.  
DOM을 건드리는 번거로운 작업을 위해 리액트를 쓰는 거니깐요.

하지만 input에서 데이터를 읽는 것은 변경시키는 것이 아니기 때문에 괜찮을 것 같습니다.

![](/images/react-41/20.png)

state를 없애고 전부 ref로 바꿔 봤습니다.

폼을 제출하면 input 을 초기화 시키는 것 또한  
nameInputRef.current.value = ' ';  
를 통해 초기화 시켰습니다.

Q. 아까 DOM 직접적으로 건들지 말라고 하셨잖아요

A. 그렇습니다. 일반적으로는 그러면 안됩니다.  
하지만 사용자가 입력한 값을 재설정하려는 경우에는 나쁘지 않은 방법입니다.

### **\- State vs Ref**

일반적으로 ref와 state 중 무엇이 더 좋을까? 라는 생각이 들것입니다.  
상황에 맞춰서 더 나은 방법을 선택하면 됩니다. 둘 다 괜찮은 방법이라고 생각합니다.

**ref가 state 보단 훨씬 코드가 적지만 DOM을 조작해야하기에 좀 복잡할 수 있습니다.**  
**state는 dom을 리액트가 관리해주기에 확실히 깔끔하지만 코드를 많이 사용해야합니다.**

그렇기에 값을 읽기만 할 거라면 ref / 값 변경을 많이 한다면 state가 좋을 것 같습니다.
