지뢰찾기 아레나에 붙은 두 번째 게임은 보물찾기입니다.

51×51 보드 한가운데 보물이 있고, 꼭짓점에서 출발해 지뢰밭을 뚫고 거기까지 가면 됩니다.

대전에서는 같은 보드의 반대편 꼭짓점에서 상대가 같이 출발합니다.

![멀티 메뉴의 보물찾기 탭 — 지뢰밭을 헤치고 같은 보드의 가운데 보물까지 먼저 도달하면 승리해요](/images/mineapp-treasure-hunt/menu.png)

기획 노트에 이렇게 적혀 있었습니다.

> 약 50x50에서 정 중앙에 있는 보물까지 먼저 닫는 사람이 승리 / 유저는 꼭지점에서 시작 / 지뢰는 보물 근처에 더 많음 / 지뢰를 건드리면 그 주변 5x5가 다시 빈 cell로 변경되면서 그 안에는 지뢰 위치가 변경됨 / 무조건 각 보드에 보물까지 갈수있는 길은 무조건 존재

만들면서 이 중 몇 개는 지웠고, 몇 개는 모양이 바뀌었습니다.

## 보드 크기가 홀수인 이유

```swift
init(size: Int = 51) {
    self.size = size | 1    // 짝수면 +1 해서 홀수로(정중앙 보장)
}
```

짝수면 정중앙 칸이 없습니다.

가운데 보물이 두 칸이나 네 칸이 되면 어느 쪽이 진짜인지 정해야 합니다.

두 사람이 반대편에서 오는 게임에서 그 반 칸이 거리 차이가 됩니다.

`| 1` 한 번으로 그 문제를 안 만들었습니다.

보물은 한 칸이 아니라 가운데 3×3 아홉 칸입니다.

한 칸이면 마지막에 그 한 칸을 정확히 눌러야 하는데, 51칸짜리 판을 폰에서 보고 있으면 그건 손가락 싸움이 됩니다.

아홉 칸 중 하나만 열면 승리이고, 이기면 나머지 여덟 칸도 같이 열어 상자를 보여줍니다.

## 지뢰보다 길을 먼저 팠습니다

지뢰를 확률로 뿌리면 운이 나쁠 때 통로가 막힙니다.

그러면 그 판은 아무리 잘해도 못 깹니다.

그래서 지뢰를 뿌리기 전에 길부터 팝니다.

```swift
// 1) 안전 통로: 꼭짓점 → 중앙. 멀티는 반대 꼭짓점에서도 한 줄 더 뚫는다.
for (r, cc) in carvePath(from: (startR, startC), to: (c, c), using: &rng) {
    g[r][cc].onPath = true
}
```

`carvePath` 는 중앙 방향으로 한 칸씩 가되 30% 확률로 살짝 비틀어서 갑니다.

곧은 대각선이면 대각선만 따라가면 된다는 게 공략이 됩니다.

마지막에는 못 닿았을 때를 대비해 직선으로 마무리해서 항상 중앙에 도달합니다.

`onPath` 가 붙은 칸에는 지뢰가 안 깔리고, 뒤에 나올 재배치에서도 제외됩니다.

다만 이 길은 화면에 안 보입니다.

안전하다는 표시가 없으니 플레이어는 여전히 숫자를 읽어 가며 찾아야 하고, 그러다 보면 결국 그 길 위로 흘러갑니다.

지뢰 밀도는 중앙으로 갈수록 올라갑니다.

```swift
/// 중앙에 가까울수록 높은 지뢰 확률(0.10 ~ 0.42).
private func mineProbability(_ r: Int, _ c: Int) -> Double {
    let cd = Double(center)
    let maxDist = cd * 1.41421356
    let d = (pow(Double(r - center), 2) + pow(Double(c - center), 2)).squareRoot()
    let t = max(0, 1 - d / maxDist)               // 중앙=1, 먼 코너=0
    return 0.10 + 0.32 * t
}
```

바깥은 10%라 성큼성큼 가는데 안쪽은 42%까지 올라갑니다.

보물이 가까워질수록 느려지는 게 이 한 줄에서 나옵니다.

## 이미 연 칸 옆만 열 수 있습니다

보물찾기가 지뢰찾기와 제일 다른 점입니다.

```swift
func isFrontier(_ r: Int, _ c: Int) -> Bool {
    for (dr, dc) in Self.neighbors where inBounds(r + dr, c + dc) {
        let n = grid[r + dr][c + dc]
        if shared {
            if n.isRevealed && n.owner == .me { return true }
        } else if n.isRevealed {
            return true
        }
    }
    return false
}
```

![보물찾기 솔로 — 좌상단에서 열린 영역, 노란 테두리가 지금 열 수 있는 칸입니다](/images/mineapp-treasure-hunt/frontier.png)

노란 테두리가 지금 열 수 있는 칸입니다.

이게 없으면 보물 위치를 아니까 처음부터 중앙을 찍는 게 최적해가 되고, 그럼 51×51 보드가 무의미해집니다.

길을 뚫는 감각은 전부 이 규칙에서 나옵니다.

깃발도 열 수 있는 칸에만 꽂을 수 있습니다.

멀리 있는 칸에 미리 표시해 두는 걸 막으려는 것인데, 뽑는 건 어디서든 됩니다.

잘못 꽂은 걸 못 지우면 그건 규칙이 아니라 벌입니다.

공유 보드에서는 조건이 하나 더 붙습니다.

내가 연 칸 옆이어야 합니다.

상대가 뚫어 놓은 통로 옆으로 건너뛰어 붙는 걸 막습니다. 그게 되면 뒤에서 따라가는 쪽이 공짜로 이깁니다.

## 지뢰를 밟으면 주변 5×5가 닫힙니다

지뢰를 밟아도 죽지 않습니다.

대신 주변 5×5가 닫히고, 그 안의 지뢰가 다시 흩어집니다.

```swift
private func penaltyReset(around r: Int, _ c: Int) {
    let radius = 2
    // 통로·보물은 보존, 나머지는 닫고 지뢰 수를 세어 둔다.
    ...
    // 재배치(방금 밟은 칸 제외)
    var spots = region.filter { !($0.0 == r && $0.1 == c) }
    spots.shuffle()
    for i in 0..<min(mines, spots.count) {
        grid[spots[i].0][spots[i].1].isMine = true
    }
    recomputeAllAdjacency()
}
```

![지뢰를 한 번 밟은 뒤 — 위 사진에서 열려 있던 오른쪽 영역이 닫히고 숫자가 바뀌었습니다](/images/mineapp-treasure-hunt/penalty-after.png)

앞 사진과 같은 판입니다.

오른쪽으로 뻗어 있던 진행이 통째로 사라지고 숫자도 달라졌습니다.

읽어 둔 정보가 날아가는 게 이 모드의 벌입니다. 체력이 아니라 시간과 지식을 잃습니다.

밟은 칸만 지뢰에서 빼는 건, 그러지 않으면 되돌아온 자리에서 곧바로 또 밟을 수 있기 때문입니다.

여기서 예상 못 한 게 하나 나왔습니다.

5×5를 닫으니 그 너머에 열려 있던 영역이 시작점과 끊겨서 공중에 떠 버렸습니다.

이미 연 곳이라 열 수 있는 칸으로도 안 잡히고, 화면에는 열린 채로 남아 있는 섬이 됐습니다.

```swift
/// 폭발(패널티)로 닫힌 영역 때문에 시작 꼭짓점과 끊겨 버린 열린 칸들을 다시 닫는다.
private func closeDisconnectedReveals() { ... }
```

시작점에서 8방향으로 이어진 열린 칸만 남기고 나머지는 닫습니다.

연결된 것만 내 것이라는 규칙을 폭발 뒤에도 지키게 한 것입니다.

## 대전에서는 되돌리지 않습니다

같은 벌을 대전에 그대로 쓸 수 없었습니다.

보드가 하나라서, 제가 밟은 5×5를 되돌리면 상대가 열어 둔 칸까지 같이 지워집니다.

남의 진행을 없애려고 일부러 밟는 게 전술이 되어 버립니다.

그래서 공유 보드에서는 벌이 완전히 다릅니다.

```swift
/// 공유 보드(온라인 대결)에서 이 횟수만큼 지뢰를 밟으면 즉시 패배한다(막 밟고 돌진 방지).
static let maxMineHits = 5

/// 지뢰를 밟으면 1.5초간 입력이 막힌다(공유 보드 패널티). 그 사이 상대가 앞서 간다.
private func applyStun() { ... }
```

밟으면 1.5초 멈춥니다. 그동안 상대는 계속 갑니다.

그리고 다섯 번 밟으면 그 자리에서 집니다.

안 그러면 숫자를 안 읽고 지뢰밭을 밟으면서 직진하는 게 제일 빠른 길이 됩니다.

죽지 않는 게임이라 그게 실제로 성립했습니다.

승패는 보물 한 칸입니다.

상대가 먼저 그 3×3에 닿으면 그 열림이 제 보드로 넘어오고, 그때 제 판이 끝납니다.

## 기획에서 지운 것

노트에 있었지만 안 만든 규칙이 둘 있습니다.

첫째는 "유저는 절반씩만 건드릴 수 있음"입니다.

보드를 대각선으로 갈라 각자 자기 절반만 파게 하려던 것입니다.

그런데 이미 연 칸 옆만 열 수 있게 하고 나니 필요가 없었습니다.

각자 자기 꼭짓점에서만 뻗어 나가기 때문에 자연히 영역이 갈립니다.

선을 그으면 그 선에 붙었을 때 뭘 해야 하는지를 또 정해야 했고, 얻는 게 없었습니다.

둘째는 "지뢰를 10개 찾을 때마다 상대 보드에 지뢰 한 개 추가"입니다.

보드를 하나만 쓰기로 하면서 사라졌습니다. 보드가 하나면 상대 보드가 없습니다.

각자 보드를 두면 이 규칙이 살지만, 그러면 상대가 어디까지 왔는지 안 보이는 게임이 됩니다.

상대가 보이는 쪽을 택했고, 공격 규칙을 포기했습니다.

## 정리

죽지 않는 게임에서는 무엇을 뺏을지가 곧 난이도입니다.

체력이 없으니 벌이 시간·정보·거리 중 하나여야 합니다.

솔로는 정보를 뺏고(5×5 되돌리기), 대전은 시간을 뺏습니다(스턴과 5회 상한).

같은 사건에 같은 벌을 주려다 대전이 망가질 뻔했습니다.

보드를 하나로 할지 둘로 할지가 규칙 목록을 결정합니다.

공격 규칙 하나가 그 선택 때문에 통째로 사라졌습니다.

기획을 다 만들지 못한 게 아니라, 앞의 결정이 뒤의 항목을 지운 것입니다.
