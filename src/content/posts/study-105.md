**• PNG와 JPG의 차이점은?**

PNG와 JPG의 가장 큰 차이점은 투명도의 차이입니다.

PNG는 RGBA / JPG는 RGB를 지원함으로써 Alpha 값을 가지고 있는 PNG만 투명도를 가집니다.

그 다음 차이점으로는 PNG는 무손실압축, JPG는 손실 압축으로써

PNG는 아무리 저장해도 같은 품질은 유지합니다. 하지만 그만큼 용량이 큽니다.

JPG는 저장 할때 마다 품질이 좀 낮아지지만 용량이 비교적 적습니다.

**• Dynamic Programming이란?**

큰 문제를 작은 문제로 쪼갠 후 한 번 풀었던 문제는 저장을 하여 두세번 풀지 않도록 하여

풀이 시간을 비약적으로 줄이는 알고리즘 기법입니다.

Dynamic Programming을 사용하기 위해서는 중복되는 부분 문제들 과 최적 부분 구조를 성립해야지 사용할 수 있습니다.

중복 부분 문제는 같은 형태의 작은 문제가 계속해서 반복되는 구조이고

최적 부분 구조는 전체 문제의 해가 작은 문제의 해로 구성되는 구조입니다.

예시로 많이 드는 것이 피보나치 수열입니다.

피보나치 수열은 F(n) = F(n-1) + F(n-2) 의 공식이 계속 반복되고 F(n-1) 또한 F(n-2) + F(n-3)으로 이루어져있습니다.

Dynamic Programming을 설명하다보면 Bottom-UP 방식과 Top-Down 방식 두가지가 있습니다.

Bottom-UP 방식은 가장 작은 문제부터 천천히 풀어나가면서 큰 문제까지 도달하는 방식이고

Top-Down 방식은 전체 문제를 재귀함수로 먼저 풀어버리면서 작은 문제를 푸는 방식입니다.

이 둘 모두 한 번 풀었던 건 저장을 해둬서 추후에는 빠르게 풀어낼 수 있습니다.

**• Virtual Memory란?**

컴퓨터는 실제 RAM이라는 메모리가 존재합니다.

가상 메모리는 실제 메모리보다 더 큰 메모리를 사용할 수 있도록 확장해주는 기술입니다.

자주 쓰는 프로세스를 RAM에 넣고 자주 쓰이지 않는 프로세스는 HDD 또는 SSD에 넣어놔서

사용자는 8GB의 RAM을 가지고 총 12GB의 여러 프로세스를 띄워둘 수 있는 것입니다.

**• Garbage Collection이란?**

개발 중 더 이상 사용하지 않는 객체 (Garbage)를 자동으로 정리해주는 것입니다.

GC가 없는 경우에는 개발자가 객체를 일일이 메모리 해제 하여 없애줘야 했었습니다.

GC가 생기고 나서부터 객체를 일일이 해제 시켜주지 않고 그냥 개발만 하면 되었습니다.

작동 방식은 간단하게 설명을 하면

heap영역에 young영역과 old 영역으로 나눠서 방금 들어온 객체는 young영역으로 갑니다.

young영역이 다 차면 사용하지 않는 객체는 버리고 사용하는 객체는 old 영역으로 갑니다.

이걸 반복하다가 old 영역이 다 차면 그때 다시 확인하고 버립니다.

GC를 사용하면 문제는 개발자는 GC가 언제 정리할지 정확히 파악이 힘들기에 갑자기 성능이 안좋아지는 순간도 존재합니다.

**• Cache란?**

자주 쓰는 데이터를 프로세스 주변에 저장해놓고 빠르게 가져다 쓸 수 있도록 해주는 저장소.

어떤 데이터를 받아올 때 큰 저장소에 갔다가 오면 매우 시간이 오래걸립니다. 이게 자주 쓰는 데이터라면 더욱이 그렇습니다.

그때 자주쓰는 데이터를 cache에 저장을 해두면 그 데이터를 가져오는 속도가 비약적으로 빨라집니다.

Cache의 문제점으로는 아무래도 쓰던 데이터를 저장해놓고 사용하는 것이기에 과거의 데이터라는 점입니다.

무조건 최신 데이터를 가져와야하는 경우에는 Cache 사용을 지양하거나 업데이트를 잘 시켜줘야합니다.

**• Database Index 추가의 장단점은?**

Database Index의 장점으로는 큰 데이터에 검색 속도가 엄청나게 빨라진다는 점과

Index로 인해서 Order by 같은 명령어를 따로 입력 하지 않아도 되는 경우에 성능이 엄청 좋아집니다.

하지만 문제로는 Index도 하나의 컬럼이기에 데이터 공간이 없을 때보다 있을 때 더 필요합니다.

또한 데이터 추가, 삭제, 업데이트를 할때 Index 까지 한번 더 계산 해줘야하기에 성능이 조금 떨어집니다.

**• 비대칭 암호화란?**

공개키와 개인키를 이용하여 데이터를 암호화 시켜서 외부로부터 데이터를 보호하거나 또는 나의 신원을 확인 시켜줄 때 사용합니다.

데이터를 누군가에게 보낼때 그 사람의 공개키로 암호화 시키게 되면 받는 사람은 개인키를 이용해서 복호화 하여 읽을 수 있습니다.

반대로 누군가에게 내가 보낸 데이터라는 것을 알려주는 전자 서명같은 것을 할 때는 내 개인키로 암호화 하여 데이터와 함께 보내면

받는 사람은 암호화 된걸 공개키로 복호화 하여 데이터와 같은지 확인을 통해서 서명을 완료합니다.

**• HDD, SSD, DRAM 각각의 성능은?**

HDD는 하드 디스크 드라이브로 실제로 원판이 돌아가면서 읽어내는 큰 저장장치입니다.

다른 것들에 비해서 싸지만 많이 느린 편입니다.

SSD는 HDD의 대체제로 나온 저장장치로써 HDD보다는 비싸지만 빠릅니다.

DRAM은 HDD / SSD와는 다르게 저장장치가 아닌 메인 메모리입니다.

그렇기에 HDD / SSD보다 훨씬 빠릅니다.

메모리의 역할로 봤을 때 HDD, SSD, DRAM 순으로 더 빠릅니다.

여기에 Cache까지 들어가면 당연히 Cache가 제일 빠릅니다.

**• GIT의 장점은?**

Git의 장점은 코드가 각자 로컬에 저장되어있기에 중앙 서버가 꺼지거나 오류가 발생해도 코드는 크게 문제가 없습니다.

또 문제가 있더라도 복구가 매우 쉽습니다.

브랜치를 만드는 것 또한 비용이 없다시피 하여 매우 싼 편이며 커밋을 누가 했는지 해시코드로 저장을 하기에

코드리뷰할때 매우 수월합니다.

**• Auto Layout의 장단점은?**

AutoLayout은 View의 위치와 크기를 설정할 때 제약조건을 이용합니다.

이렇게 했을 때 장점은 여러가지 다양한 화면 크기를 한가지 레이아웃에 맞춰서 사용자에게 동일하게 보여줄 수 있습니다.

또한 화면 회전에도 따로 계산을 해주지 않아도 내부적으로 계산을 해서 보여주기에 매우 편합니다.

내부적으로 계산을 하기에 단점으로 제약조건을 엄청나게 만들시 성능이 떨어질 수 있습니다.

또한 뷰 마다 제약조건을 가지고 있는데 어떤 뷰 하나를 잘 못 건드렸을 때 어디서 문제가 생겼는 지 디버깅 하기 꽤나 어렵다는 점이 있습니다.

**• MVC 패턴이란?**

Model - View - Controller의 약자로 코드를 깔끔하게 관리하기 위한 디자인 패턴입니다.

Model은 사용자가 사용하는 데이터들을

View는 화면

Controller는 Model과 View를 관리하는 역할을 하여 코드를 나눕니다.

기본적으로 코드가 깔끔해지고 자기가 맡은 역할만 하기에 성능 또한 엄청나게 좋아집니다.

하지만 swift에서는 viewController 이름 처럼 view와 Controller가 긴밀하게 붙어있기에

ViewController에 너무 많은 코드가 들어가버리면 또 유지보수가 힘들어지기도 합니다.

**• KVC와 KVO란?**

KVC 는 Key Value Coding의 약자로써

문자열 Key또는 KeyPath를 이용하여 Value를 간접적으로 가져오거나 수정을 하는 패턴입니다.

Objective-C 런타임에 실행되기에 NSObject를 상속해야합니다. 또한 문자열을 이용하기에 문자열에 오타라도 있을 경우에는

런타임 에러가 발생합니다.

KVO는 Key Value Observing 의 약자로써

값의 변화를 옵져빙하여 값이 변경될때마다 return 받는 패턴입니다.

KVC와 KVO 둘다 Objective-C 일 때 사용하던 패턴으로써 문자열 Key를 이용하기에 타입 안정성이 떨어집니다.

Swift가 지향하는 것이 타입 안정성이기에 최근에는 KVC와 KVO 말고 대체로 사용하는 것들이 많이 생겼습니다.

그럼에도 알아야하는 이유는 Objective-C 호환이 필요하거나 Obj-C 라이브러리를 사용할때 아직도 사용하는 것이 존재합니다.

**• Swift의 특징은?**

Swift는 apple에서 만든 언어로써

가장 중요한 특징은 타입 안정성이 있습니다.

옵셔널 값이나 guard let 같은 구문을 이용하여 타입을 강제시키도 하고 컴파일 시점에서 타입을 확실히 정하거나 nil 처리를 하도록 합니다.

또한 프로토콜 지향 프로그래밍으로써 프로토콜과 익스텐션을 사용하여 좀 더 유연한 코드를 만들 수 있습니다.

**• Higher Order Function이란?**

함수를 인자로 받거나 함수를 결과로 반환하는 함수입니다.

Swift에서는 대표적으로 map, reduce forEach등등이 있습니다.

고차 함수를 사용하게 되면 코드가 엄청나게 간결해져서 보기에 좋고 재사용에도 좋습니다.

**• Method Swizzling이란?**

기존에 실행되고 있는 메서드를 다른 메서드로 교체를 하는 것입니다.

예로는 ViewController의 생명주기인 ViewDidLoad같은 것들이 있습니다.

메서드 스위즐링을 사용하지 않고 하는 방법도 있습니다. 오버라이딩을 사용하거나 상속을 사용하면 되는데

이는 ViewController 마다 해줘야하기에 같은 코드를 계속 써줘야하는 번거로움이있습니다.

매서드 스위즐링을 사용하게 되면 공통로직을 한번에 추가할 수 있습니다.

하지만 이미 존재하는 매서드를 바꾸는 것이기에 아무렇게나 막 사용하면 에러가 발생하기에

매우 조심스럽게 사용해야합니다.

**• HTTP/2의 특징은?**

HTTP/1.1을 대체로 만들어진 HTTP/2는

메세지를 text로 보낼 수 있는 1.1에 비해 바이너리 프레임으로 인코딩하여 영상, 사진을 보낼 수 있습니다.

또한 1.1의 경우 TCP 커넥션에 하나를 보내면 응답이 올때까지 다음은 기다렸어야했습니다.

그렇기에 여러개의 데이터를 보낼때는 TCP 커넥션을 여러개를 만들었어야했는데

HTTP/2는 한개의 TCP 커넥션에 여러개의 정보를 보낼수 있기에 매우 빠르게 전송이 가능합니다.

**• Memory Leak의 대처방법은?**

Swift는 GC가 아닌 ARC를 사용합니다. ARC는 각 인스턴스에 참조 카운트를 계산해서 0이 되면 자동으로 메모리를 해제시켜줍니다.

이 때 인스턴스 끼리 강한참조가 걸려서 모든 메모리를 해제시켜야하는데 서로 인스턴스끼리 참조카운트가 1로 남아있어서

메모리 해제가 되지 않는 상태가 Memory Leadk입니다.

이때는 weak를 사용하여 강한 참조에서 약한 참조로 변경을 해주면 됩니다.

클로저 내부에서 self를 사용하면서도 메모리 리크가 많이 걸리기 때문에 클로저 내부 self 앞에 weak를 작성해주는 것도 방법입니다.

**• 이미지 리스트의 성능 향상법은?**

이미지를 캐시에 저장을 해둬서 스크롤 하면서 계속 다운을 받지 않고 바로바로 쓸 수 있도록 합니다.

또한 셀을 재사용해서 매번 새로운 뷰를 만들지 않도록 합니다.

AutoLayout의 셀 크기를 계산을 해놔서 오버헤드를 줄이는 것도 방법입니다.

이미지를 메인쓰레드에서 다운 받는 것이 아니라 백그라운드에서 처리한다음 메인쓰레드에 가져오는 것도 성능 향상에 도움이 될 것 같습니다.

**• 1Byte가 뭐죠?**

1Byte는 8Bit 입니다,.

Bit는 컴퓨터의 최소 단위로 0과 1로 이뤄어져 있으며 상태를 관리합니다.

**• 1Byte로 표현 간으한 양수, 음수 범위**

1Byte는 8Bit이기에 2^7  / -128 ~ 127 까지 가능합니다.

**• 부동 소수점이 뭔가요?**

소수점을 가진 실수를 2진법으로 처리할때 소수점을 움직여서 처리합니다.

부동소수점은 부호 , 지수 , 가수 이렇게 3부분으로 나누어져있습니다.

고정 소수점보다 훨씬 큰고 작은 수를 넣을 수 있습니다.

**• 부동소수점이 가진 문제가 뭔가요?**

0.1이나 0.2 처럼 소수점을 2진법으로 바꾸게 되면 무한히 나아가게 됩니다.

그런데 우리의 메모리양은 무한하지 않기 때문에 반올림하여 최대한 근사값으로 넣어야합니다.

그러다보니 계산식을 넣게 되면 우리의 머리속으로는 맞는 답이 컴퓨터는 틀리다고 답변 하는 경우가 있습니다.

**• 오버플로우, 언더플로우가 부동소수점이 가진 문제가 맞나요?**

오버 플로우와 언더플로우는 부동소수점이 가진 문제가 맞습니다.

정말 큰 수 또는 정말 작은 수를 표현하게 되면 문제가 일어나게 됩니다.

그런데 이 문제는 부동 소수점만의 문제라기보다는 정수에서도 동일하게 일어나는 것입니다.

**• Swift에서 연산을 할 때 부동소수점 이슈때문에 틀린답이나온다던가 하는것**

0.1 + 0.2 == 0.3 을 하게 되면 아니라고 합니다.

위에서 설명한 것처럼 0.1 과 0.2를 2진법으로 변경하게 되면 가수 부분이 무한히 나아가게 되므로 알맞은 저장소 만큼 끊어내게 됩니다.

그러면 엄청나게 근소한 차이가 나타나게 되는 데 더하게 되면 0.3 과 비슷한 숫자이지만 0.3과 완전히 동일하지는 않게 되는 것입니다.

이 부분을 해결하게 위해서는 최대한 정수로 계산을 진행을 하는 방식이 있습니다.

**• base 64란?**

 base64는 바이너리 데이터를 Text로 인코딩을 할 때, 64개의 문자열로 인코딩을 진행합니다.

사진이나 영상 같은 것은 JSON으로 쉽게 보내기 위하여 사용합니다.

**• 가상메모리를 사용하는 목적**

컴퓨터의 실제 메모리보다 더 큰 메모리로 사용할 수 있게 끔 확장시키기 위합니다.

자주 쓰는 페이지만 RAM에 두고 나머지 많이 사용하지 않은 프로세스는 디스크에 넣으므로써

총 프로세스가 실제 메모리보다 높더라도 동작할 수 있게 합니다.

또한 가상메모리를 사용하므로써 가상주소 공간을 할당받는데 이를 이용하여 프로세스가 다른 프로세스의 메모리를 침범하지 못하도록 보호하는 기능도 합니다.

**• 메모리가 엄ㅊ어 크고 프로세스가 딱 하나일때 가상메모리 안씀?**

아무리 그래도 사용합니다.

왜냐하면 확장할 필요가 없더라도 가상주소공간을 이용하여 다른 프로세스의 메모리를 침범하지 못하게 하는

격리의 역할도 있으며 추후에 다른 프로세스가 들어왔을 때 RAM에 과부하가 일어날수도 있습니다.

**• 32bit와 64bit가 가질수있는 virtual memory 최대 크기**

2^32 = 4GB 

2^64 = 엄청 큼 -> 주로 수십 TB 로만 사용중입니다.
