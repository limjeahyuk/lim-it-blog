## 디자인 토큰

최근에 디자인 시스템을 혼자도 만들어보고 그러다가 Mantine 라이브러리를 base로 해서 묶는 작업을 진행했습니다.

그러다가 token에 대해서 생각이 들었습니다.



디자이너와 협업을 하게 될때 token 정하게 됩니다.

이 token이 하는 일을 먼저 알아야할 듯합니다.

### 토큰이 필요한 이유

> 디자인 토큰은 디자인 시스템에서 색상, 타이포그래피, 간격, 그림자 같은 시각적인 디자인 결정을 하드코딩된 고정값이 아닌 이름이 부여된 변수로 저장하고 관리하는 역할을 합니다.



디자인 시스템 내에서 토큰이 수행하는 핵심 역할은 다음과 같습니다.

- **플랫폼 간 일관성 유지 (Cross-platform Consistency)**   
토큰은 특정 언어나 플랫폼에 종속되지 않는 중립적인 데이터로 저장됩니다.   
이 데이터를 웹(CSS, SCSS), iOS(Swift), Android(XML) 등 각 플랫폼에 맞는 코드로 자동 변환하여, 사용자가 어떤 기기로 접속하든 동일한 시각적 경험을 제공합니다.
- **디자이너와 개발자의 공통 언어 (Single Source of Truth)**   
디자이너가 Figma에서 `#0052CC`라는 특정 파란색을 사용할 때, 개발자에게 "헥사 코드 0052CC를 써주세요"라고 하는 대신 `color-brand-primary`라는 토큰 이름을 전달합니다. 양쪽 모두 동일한 토큰을 참조하므로 커뮤니케이션 오류가 사라집니다.
- **압도적인 유지보수 효율성**   
브랜드의 메인 컬러가 파란색에서 보라색으로 변경되어야 할 때, 코드베이스와 디자인 파일 곳곳에 흩어진 수천 개의 컬러 값을 일일이 찾아서 수정할 필요가 없습니다.  
중앙 시스템에서 `color-brand-primary`의 값만 보라색으로 업데이트하면 연결된 모든 프로덕트에 일괄 적용됩니다.
- **테마 및 다크 모드 확장성**   
토큰을 사용하면 다크 모드나 새로운 브랜드 테마를 쉽게 구축할 수 있습니다.   
`color-background-default`라는 토큰 하나에 라이트 모드일 때의 값(흰색)과 다크 모드일 때의 값(검은색)을 매핑해 두면, 시스템 설정에 따라 화면이 자연스럽게 전환됩니다.

**예시 비교**

- **하드코딩 (토큰 미사용):** 버튼 배경색 = `#1A73E8`, 텍스트 색상 = `#FFFFFF` (수정 시 모든 코드를 찾아 바꿔야 함)
- **디자인 토큰 사용:** 버튼 배경색 = `color-action-primary`, 텍스트 색상 = `color-text-on-primary` (값 변경 시 토큰의 정의만 수정하면 됨)



이처럼 일관성과 유지보수 측면에서 아주 도움이 되기 때문에 꼭 사용해주는 편이 좋습니다.



이런 토큰에도 단계가 있습니다.

### 디자인 토큰의 단계

<img src="https://res.cloudinary.com/m1zcmsux/image/upload/c_limit,f_auto,q_auto,w_1600/v1791857724/us2yecitl9a0polh9tqf.png" alt="설명" width="590">



**1. 글로벌 토큰 (Global / Reference Tokens)**



디자인 시스템의 가장 기초적인 값입니다. 

문맥이나 목적이 부여되지 않은 상태로, 모든 색상 팔레트나 타이포그래피 스케일을 정의합니다.

- **특징:** 하드코딩된 값(Hex, px 등)을 직접 품고 있으며, 시스템 내 모든 디자인 요소의 근간이 됩니다.
- **이름 예시:** `color-blue-500`, `spacing-16`, `font-size-24`

**2. 시맨틱 토큰 (Semantic / Alias Tokens)**



글로벌 토큰을 참조하여 의미와 목적을 부여한 토큰입니다. 

어디에, 왜 쓰이는지를 나타내며 다크 모드 같은 테마 전환의 핵심 역할을 합니다.

- **특징:** 하드코딩된 값이 아닌 글로벌 토큰을 참조값으로 가집니다.
- **이름 예시:** `color-action-primary` (값: `{color-blue-500}`), `color-text-danger` (값: `{color-red-500}`)

**3. 컴포넌트 토큰 (Component Tokens)**



특정 UI 컴포넌트에만 종속되는 토큰으로, 시맨틱 토큰을 참조합니다. 개발자가 컴포넌트를 만들 때 가장 직관적으로 사용할 수 있습니다.

- **특징:** 적용 범위가 단일 컴포넌트로 매우 좁습니다. 시스템의 복잡도를 높일 수 있어 모든 조직이 필수로 사용하지는 않습니다.
- **이름 예시:** `button-primary-background` (값: `{color-action-primary}`)

**단계별 비교 요약**


|             |                        |                          |                        |
| ----------- | ---------------------- | ------------------------ | ---------------------- |
| **단계**      | **토큰 이름 예시**           | **매핑되는 값 (Value)**       | **역할**                 |
| **1. 글로벌**  | `color-blue-500`       | `#1A73E8`                | 사용할 수 있는 모든 옵션(팔레트) 정의 |
| **2. 시맨틱**  | `color-action-primary` | `{color-blue-500}`       | 특정 목적(주요 액션)에 색상을 할당   |
| **3. 컴포넌트** | `button-primary-bg`    | `{color-action-primary}` | 특정 컴포넌트(버튼)에만 적용되도록 한정 |




이런 다단계 구조의 가장 큰 장점은 **수정의 파급력을 제어**할 수 있다는 것입니다. 

만약 브랜드의 메인 액션 색상을 파란색에서 보라색으로 바꾸고 싶다면, 시맨틱 토큰인 `color-action-primary`가 참조하는 글로벌 토큰을 `color-purple-500`으로 변경하기만 하면 됩니다. 그러면 이를 참조하고 있는 모든 버튼, 링크, 체크박스 컴포넌트가 일제히 업데이트됩니다.



이렇기에 추후에 수정사항이 있을 때 메우 빠르고 간단하게 수정이 가능한 점이 개발자 입장에서 매우 좋은 점이라고 생각합니다.

### 실제 token code



**1. 글로벌 토큰 (**`global.css` **또는** `palette.css`**)** 

순수한 색상, 간격 등의 원시 값만 정의합니다. 브랜드 컬러 시스템이 아예 갈아엎어지지 않는 한 **가장 수정이 적게 일어나는 파일**입니다.

```
/* global.css */
:root {
  --color-blue-500: #1A73E8;
  --color-gray-100: #F5F5F5;
}

```



**2. 시맨틱 토큰 (**`semantic.css` **또는** `theme.css`**)** 

글로벌 토큰을 불러와 용도를 지정합니다. 라이트 모드(`theme-light.css`)와 다크 모드(`theme-dark.css`)를 분리해서 관리하기 가장 좋은 단계입니다.

```
/* theme.css */
@import 'global.css';

:root {
  --color-action-primary: var(--color-blue-500);
}

```



**3. 컴포넌트 토큰 (각 컴포넌트 파일 내부에 위치)** 

컴포넌트 토큰은 중앙의 커다란 파일에 모아두는 것이 아니라, 해당 컴포넌트를 정의하는 코드 바로 옆에 두는 방식을 많이 사용합니다. 

버튼을 수정하고 싶으면 버튼 폴더만 열면 되도록 만드는 것입니다.

```
/* Button.module.css (버튼 컴포넌트 전용 스타일 파일) */
.button-primary {
  /* 버튼 내부에서만 쓸 변수를 여기서 정의하고 사용 */
  --btn-bg: var(--color-action-primary);
  
  background-color: var(--btn-bg);
}

```
