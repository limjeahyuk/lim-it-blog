## CloudeCode Token 절약

> 요즘 모든 개발자들이 CloudeCode를 매우 많이 사용합니다.  
> 모두가 AI를 사용한다면 조금 더 경쟁력을 얻기 위해서는 남들보다 AI를 더 잘 다룰 줄 알아야한다고 생각했습니다.



### Token

> AI 모델이 텍스트를 인식하고 처리하는 가장 작은 정보 조각입니다.
>
> Claude의 경우 토큰 하나가 대략 영어 3.5자 정도에 해당하고 언어에 따라 토큰의 양도 다릅니다.



모델은 텍스트를 그대로 읽지 않습니다.

입력된 글자열을 먼저 토큰 열로 인코딩한 뒤 처리하고, 출력도 토큰 단위로 하나씩 생성합니다.

#### 입력 토큰 / 출력 토큰


| 비교 항목   | 입력 토큰                                                                             | 출력 토큰                        |
| ------- | --------------------------------------------------------------------------------- | ---------------------------- |
| 방향      | User -&gt; AI                                                                     | AI -&gt; User                |
| 포함되는 내용 | 시스템 프롬프트<br>messages의 모든 메세지<br>- 이미지, 문서, 도구<br>tools 파라미터의 도구<br>이전 턴의 대화 기록 전체 | AI 가 작성한 코드, 답변, 터미널 명령어 등등  |
| 비용      | 상대적으로 저렴                                                                          | 입력 토큰보다 비쌈                   |
| 처리 속도   | 수만 토큰의 코드도 순식간에 읽어냄                                                               | 토큰을 순차적으로 생성하므로 응답하는데 시간이 걸림 |




- 입력 토큰은 병렬로 한꺼번에 처리합니다.
  - AI 모델은 사용자가 입력한 수만 개의 토큰을 동시에 한 번에 읽고 파악합니다.
  - 연산 속도가 매우 빠르고 서버 자원을 잠깐 사용하기에 저렴합니다.
- 출력 토큰은 순차적으로 생성합니다.
  - 출력 토큰은 병렬화가 불가능하고 토큰 하나씩 순차적으로 생성합니다.
  - 첫 단어를 쓴 뒤 그 단어를 바탕으로 다음 단어를 예측하는 과정을 끊임없이 반복합니다.

#### 입력 토큰을 적게 쓰는 방법

- Claude.md 정리
  - [Claude.md](http://Claude.md) 파일은 사용자가 프롬프트를 입력할 때마다 항상 백그라운드에서 함께 전송되어 토큰으로 계산 됩니다.
- 컨텍스트 정리
  - 한 번 대화 때마다 이전 대화내용들까지 모두 받아옵니다. 그렇기 때문에 한 대화창에서만 진행을 하게 되면 정말 짧은 질문을 해도 어마어마한 입력 토큰이 나갈수도 있습니다.
  - `/clear` 또는 `/compact` 를 이용하여 정리를 진행합니다.

#### 출력 토큰을 적게 쓰는 방법

- 불필요한 말 생략
  - 인사말, 쓸데없이 긴 작동원리를 덧붙이는 경향이 있습니다.
  - 수정한 부분만 간결하게 말하도록 요구합니다.

- 전체 파일 대신 차이점만 요구
  - 결과물을 요구할 때 파일 전체를 받는 것보다는 달라진 부분만 보는 것이  
  아무래도 더 적은양의 출력 토큰을 받을 수 있습니다.

- 작업을 작게 쪼개기
  - 큰 기능을 한번에 요구하게 되면 엄청난 코드를 쓰다가 멍청해지거나 이상한 길로 빠지게 되는 경우가 있습니다.
  - 작업을 작게 쪼개서 병렬구조로 따로따로 시켜서 맡은 것만 해결할 수 있도록 합니다.

### Claude.md

Claude Code 세션은 매번 빈 컨텍스트로 시작합니다.  
그런 세션 간에 지식을 넘겨주는 장치가 두가지가 있습니다.



- 사용자가 직접 작성하는 Claude.md
- claude가 스스로 기록하는 auto memory



Claude.md는 시스템 프롬프트 뒤에 사용자 메시지로 Claude에게 전달됩니다.

즉, **강제 설정이 아니라 컨텍스트이고, 엄격한 준수가 보장되지 않습니다.**


| 범위    | 경로                                     | 용도                    |
| ----- | -------------------------------------- | --------------------- |
| 조직 정책 | `/etc/claude-code/CLAUDE.md` 등         | 전사 표준 (개인 설정으로 제외 불가) |
| 사용자   | `~/.claude/CLAUDE.md`                  | 모든 프로젝트 공통 개인 취향      |
| 프로젝트  | `./CLAUDE.md` 또는 `./.claude/CLAUDE.md` | 팀 공유, 버전관리 대상         |
| 로컬    | `./CLAUDE.local.md`                    | 개인용, `.gitignore` 대상  |


#### 1. 200줄을 넘기지 않기.

[CLAUDE.md](http://CLAUDE.md)는 매 세션 시작 시 컨텍스트에 올라가 대화와 함께 토큰을 소모합니다. 

200줄 미만이 목표이고, 길어질수록 토큰도 늘고 준수율도 떨어집니다.

#### 2. `@import`는 토큰을 아껴주지 않습니다

`@path` 임포트로 파일을 쪼개는 건 정리에만 도움이 되고, 임포트된 파일도 시작 시점에 그대로 컨텍스트에 로드되므로 절약 효과가 없습니다.

#### 3. path-scoped rules

`.claude/rules/`에 주제별 파일을 두고 frontmatter에 `paths`를 지정하면, 해당 패턴의 파일을 Claude가 읽을 때만 로드됩니다.

```markdown
---
paths:  
   - "src/api/**/*.ts"
---

# API 규칙
- 모든 엔드포인트에 입력 검증 필수
- 표준 에러 응답 포맷 사용

```

`paths` 없는 rule은 무조건 로드되니 주의하세요.

그리고 특정 작업에서만 필요한 다단계 절차라면 rules보다 **skill**이 낫습니다

— skill은 호출하거나 관련성이 있다고 판단될 때만 로드됩니다.

#### 4. 유지보수 메모는 HTML 주석으로

블록 레벨 HTML 주석(`<!-- ... -->`)은 컨텍스트에 주입되기 전에 제거됩니다.   
사람용 메모를 토큰 소모 없이 남길 수 있습니다.

#### 5. 모노레포라면 `claudeMdExcludes`

상위 디렉터리의 다른 팀 [CLAUDE.md](http://CLAUDE.md)가 딸려 오는 걸 막습니다. `.claude/settings.local.json`에 넣으면 내 머신에만 적용됩니다.

```json
{ "claudeMdExcludes": ["**/monorepo/CLAUDE.md"] }
```

하위 디렉터리의 [CLAUDE.md](http://CLAUDE.md)는 시작 시가 아니라 그 디렉터리 파일을 읽을 때 로드되므로, 오히려 이걸 적극 활용하는 게 좋습니다.

#### 6. 구체성이 곧 토큰 절약

검증 가능할 만큼 구체적으로 쓰세요. 

- **포맷 잘 맞춰** 보다 **2칸 들여쓰기**
- **테스트해** 보다 **커밋 전** `npm test` **실행**
- **파일 정리해** 보다 **API 핸들러는** `src/api/handlers/`**에** 



모호한 지시는 Claude가 엉뚱하게 작업하고 다시 고치는 왕복을 부르는데, 그

왕복이 [CLAUDE.md](http://CLAUDE.md) 몇 줄보다 훨씬 비쌉니다.

또한 서로 모순되는 규칙이 있으면 Claude가 임의로 하나를 고를 수 있으니, 여러 계층의 파일을 주기적으로 정리해야합니다.

### Prompt Caching

프롬프트 캐싱은 AI가 방대한 코드나 문서를 매번 처음부터 다시 읽지 않도록, 최근에 읽어들인 정보를 임시 메모리에 저장해 두는 기술입니다. 

이 기능을 활용하면 대화가 길어지거나 코드베이스가 커져도 입력 토큰 비용을 획기적으로 줄일 수 있습니다.

- **단기 기억 장치 역할**
  - 사용자가 큰 소스 코드 파일이나 프로젝트 배경 지식을 제공하면, AI는 첫 질문 때 이를 분석한 뒤 약 5분 동안 시스템 캐시에 보관합니다. 
  - 이 시간 내에 후속 질문이 들어오면 처음부터 다시 읽지 않고 저장된 맥락을 바로 꺼내어 씁니다.
- **약 90% 요금 할인**
  - 첫 질문 시 캐시에 데이터를 기록할 때는 기본 입력 요금보다 약간 더 비싼 비용(약 1.25배)이 발생합니다. 
  - 하지만 두 번째 질문부터 캐시에서 데이터를 불러올 때는 기본 입력 요금의 **단 10% 수준**만 과금되어 전체적인 비용이 대폭 감소합니다.
- **체감 대기 시간 단축**
  - 수만 줄의 코드를 매번 다시 연산하는 과정을 건너뛰기 때문에, 질문 입력 후 첫 번째 글자가 터미널에 출력되기까지 걸리는 시간이 순식간으로 줄어듭니다.
- **Claude Code 자동 적용**
  - Claude Code는 사용자가 터미널에서 지속적으로 대화하며 코드를 수정할 때 비용 폭탄을 맞지 않도록, 내부적으로 이 프롬프트 캐싱 시스템을 자동으로 활용합니다.

### Compact &amp; Clear

> `/compact`와 `/clear`는 대화가 길어짐에 따라 눈덩이처럼 불어나는 이전 대화내용을 관리합니다.  
> 대화내용을 관리하므로써 토큰까지 절약 가능합니다.



&nbsp;

`/compact` **(대화 압축)**

- **작동 방식**
  - 지금까지 나눈 대화에서 자잘한 질문이나 길게 출력된 에러 로그 등은 메모리에서 잘라내고, 핵심 맥락만 요약하여 남깁니다.
- **사용 타이밍**
  - 하나의 기능 개발을 계속 이어서 하고 싶지만, 세션이 너무 길어져 비용이 부담되거나 AI가 초반 지시사항을 자꾸 잊어버릴 때 입력하면 좋습니다.

`/clear` **(대화 완전 초기화)**

- **작동 방식**
  - 현재까지의 모든 대화 기록을 완전히 삭제하고 백지상태에서 새로운 세션을 시작합니다.
- **사용 타이밍**
  - 기존 작업을 끝내고 완전히 다른 새로운 작업을 시작할 때 사용합니다. 이전 대화 기록이 새 작업에 방해가 되는 컨텍스트 오염을 막고 비용을 아예 초기화할 수 있습니다.
