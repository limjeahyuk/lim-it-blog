#### HDD

> 하드 디스크 드라이브 라고 하는 컴퓨터의 데이터를 저장하는 장치입니다.  
> 자기 디스크를 기계적으로 돌리면서 데이터를 읽고 쓰는 저장장치

![](/images/study-101/1.png)

-   장점
    -   저렴한 가격 / 대용량 : SSD 대비 기가바이트당 비용이 훨씬 저렴해 대용량 저장에 경제적.
    -   데이터 복구 가능성 : 문제 발생시 SSD 보다 데이터 복구 가능성이 높습니다.
    -   검증된 기술 : 오랜 기간 사용된 기술로 안정적.
-   단점
    -   느린 속도: 회전하는 디스크와 헤드를 사용하기에 속도가 느립니다.
    -   충격에 취약 : 작동 중 충격에 고장나기 쉬우며, 전원이 켜진 상태에서의 충격은 치명적.
    -   소음 & 발열 : 내부 부품이 고속 회전하기에 소음과 열이 발생.
    -   높은 전력 소모 & 무게 : SSD에 비해 전력을 더 소모하고 무겁습니다.
-   사용처
    -   NAS, 백업 서버, CCTV 저장장치
    -   사진/영상 등 덩치 큰 자료 오래 쌓아두는 용도
    -   클라우드 / 데이터센터에서도 “용량 위주” 스토리지 계층에 사용

* * *

#### SSD

> Solid State Drive 는 플래시 메모리를 이용해 데이터를 저장하는 저장장치.  
> HDD와 다르게 기계 부품이 없이 반도체 칩을 사용합니다.

![](/images/study-101/2.png)

-   장점  
    -   HDD보다 속도가 빠릅니다.
    -   기계장치가 없기에 충격에 강합니다.  
        → 고장이 적고 소음이 발생하지 않습니다. 또 매우 가볍습니다.
    -   전력 소모가 적고 발열이 낮아서 노트북 배터리 수명 연장 및 시스템 안정성에 기여합니다.
-   단점
    -   HDD보다 용량 대비 비쌉니다. → 대용량 저장에는 부담이 됩니다.
    -   고장 시 데이터 복구가 어렵고 비용이 많이 듭니다.

* * *

#### DRAM

> Dynamic Random Access Memory  
> 컴퓨터와 전자 장치에서 널리 사용되는 메모리 유형, 데이터 저장과 처리를 위한 임시 기억 창지

우리가 보통 말하는 램 16GB 같은 것이 바로 DRAM 모듈입니다.

데이터를 저장하는 데 전기적인 축전기와 트랜지스터를 사용합니다.

-   동적 메모리  
    DRAM은 시간이 지나면 저장된 데이터가 사라질 수 있습니다.  
    데이터를 유지하기 위해서는 리프레쉬가 필요합니다.
-   휘발성  
    전원이 꺼지면 모든 데이터가 사라집니다.
-   속도가 매우 빠릅니다.  
    CPU가 바로 보는 데이터 창고 역할이기에 속도 측면에서 월등합니다.
-   가격이 매우 비쌉니다.

* * *

#### HDD, SSD, DRAM

HDD와 SSD는 같은 역할을 하는 영구 저장장치입니다.

하지만 DRAM의 경우에는 작업용 메모리로써 HDD, SSD와 역할 자체가 다릅니다.

그럼에도 성능을 메모리 계층 구조로 비교는 가능합니다.

![](/images/study-101/3.png)

위 사진 처럼 하드 디스크 (HDD, SSD), 메모리 (DRAM), cache 단계별로 성능을 확인 할 수 있습니다.

컴퓨터는 층층이 쌓인 저장소 구조이기에 위에서 아래로 갈 수록 느리지만 용량이 크고 쌉니다.

계층

역할

**속도**

용량 / 가격

CPU Cache

CPU 바로 옆 작업 메모리

**초초고속**

매우 작고 매우 비쌈

DRAM (RAM)

실행 중 프로그램 작업 공간

**초고속**

작고 비쌈

SSD

OS/앱/데이터 저장

**빠름**

중간

HDD

백업/대용량 저장

**느림**

싸고 매우 큼

항상 그렇듯이 무조건적으로 이것이 좋다기보다는 각 역할에 맞춰서 사용을 해야합니다.

-   HDD/SSD는 **영구 저장 계층**
-   DRAM은 **실행 중 데이터 계층**
-   CPU Cache는 **CPU 바로 옆 초고속 캐시 계층**

그리고 이 계층 구조 때문에:

> 자주 쓰는 데이터는 캐시/메모리에 최대한 올려두고,  
> 디스크/네트워크은 정말 필요할 때만 접근하도록 설계하는 것이  
> 곧 **캐시/버퍼/메모리 튜닝**이고, 성능 최적화의 핵심입니다.

#### “데이터 하나 읽을 때” 실제로 벌어지는 일

예를 들어, 앱에서 어떤 데이터(파일/DB 결과)를 읽는다고 해볼게요.

1.  **CPU 캐시에서 찾기**
    -   제일 먼저 CPU는 자기 캐시(L1/L2/L3)에 이 데이터가 있는지 봅니다.
    -   있으면 → **최고 속도** (ns 단위로 끝남)
2.  **없으면 DRAM(RAM)에서 찾기**
    -   CPU 캐시에 없으면 DRAM에서 가져옴.
    -   이때도 여전히 빠른 편이지만, 캐시보단 느림.
3.  **DRAM에도 없다면 OS가 SSD/HDD에서 읽어오기**
    -   OS의 페이지 캐시/버퍼에 없다면
    -   최종적으로 **SSD/HDD에서 파일 블록을 읽어와서 DRAM으로 올림**
4.  **그다음부터는 RAM/캐시에서 재사용**
    -   한 번 SSD/HDD → RAM으로 올라온 데이터는
    -   OS, DB, 앱 단에서 **캐시/버퍼에 남겨두고** 다음에 더 빨리 쓰려고 함.

이래서 컴퓨터를 사용하다보면 처음 실행은 느렸는데 두 세번째부터는 좀 빠른 느낌이 나는 경우가 있습니다.
