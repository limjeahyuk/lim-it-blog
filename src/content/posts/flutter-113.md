### Dart는 어떤 언어인가?

Dart는 구글이 만든 **클라이언트 앱 개발에 최적화된 언어**입니다.

Flutter의 공식 언어로, Flutter 앱에서 UI부터 상태관리/비즈니스 로직까지 대부분을 Dart로 작성합니다.

Dart의 방향성은 한 줄로 요약하면

> **생산성 높은 문법 + 강한 타입 시스템 + (웹/모바일에서) 빠르게 실행 가능한 구조**

특히 Flutter에선 Dart 코드가 플랫폼에서 잘 돌아가도록 **컴파일 전략이 2가지**로 나뉩니다.

-   **개발 모드(JIT: Just-In-Time)**  
    코드를 즉시 컴파일해서 실행 → **Hot Reload**에 강함
-   **릴리즈 모드(AOT: Ahead-Of-Time)**  
    미리 네이티브 코드로 컴파일 → **실행 성능/시작 속도**에 유리

이 구조 때문에 개발은 **빠르고, 배포는 성능 좋게**라는 느낌이 나옵니다.

* * *

### Dart의 핵심 특징

#### 1) 타입 안정성이 있는 언어(Statically typed) + 타입 추론

Dart는 기본적으로 타입이 있고, 컴파일러가 타입을 추론해주기도 합니다.

> int count = 3;  
> var name = "혁쨩";  // String으로 추론

-   장점: 규모가 커질수록 안정적(리팩토링/자동완성/오류 방지)
-   단점: 빠르게 대충 만들 때는 타입/널 처리 때문에 귀찮을 수 있음

#### 2) Null Safety(널 안정성)

Dart는 “널이 될 수 있는 변수”를 명확히 구분합니다.

> String title = "Hello";  
> String? subtitle; // null 가능

-   장점: 런타임 크래시(Null 관련) 크게 줄어듦
-   단점: 처음엔 ?, !, ?? 같은 처리 문법이 낯설 수 있음

#### 3) async/await 기반의 비동기 처리

네트워크, 파일, DB 같은 작업이 많은 모바일 개발에 잘 맞게 설계됐습니다.

> final data = await fetchData();

-   장점: 비동기 코드가 읽기 쉬움
-   단점: Future/Stream 개념을 제대로 잡아야 꼬이지 않음

#### 4) 객체지향(OOP) + 함수형 스타일도 가능

클래스 기반 구조(OOP)가 기본이고, 함수형스럽게도 작성 가능합니다.

* * *

### Dart의 장점

#### 1) Flutter를 위해 “딱 맞게” 설계된 언어

UI를 선언적으로 작성하고(위젯 트리), 상태 변경에 따라 다시 그리는 패턴에 잘 맞습니다.  
즉, Flutter 개발 생산성이 높아집니다.

#### 2) 개발 경험이 좋다 (Hot Reload의 기반)

JIT + Hot Reload로 UI 수정 사이클이 빠릅니다.  
**화면 만들면서 바로 확인**이 가능해서 학습/개발 속도가 빨라집니다.

#### 3) 문법이 비교적 친숙하다

Java/C#/JavaScript/Swift 경험이 있으면 금방 적응합니다.

-   클래스/메서드 구조는 Java/C# 느낌
-   async/await는 JS/Swift 경험자에게 익숙
-   컬렉션 다루기는 현대 언어 감성(리스트/맵 편함)

#### 4) 성능/배포에 유리한 컴파일 전략(AOT)

릴리즈에서 네이티브로 컴파일되니, **스크립트 언어** 같은 성능 한계가 상대적으로 적습니다.

#### 5) 툴링이 괜찮습니다.

포맷터(dart format), 린트, 패키지 매니저(pub), 분석기(analyzer) 등이 잘 갖춰져 있습니다.

* * *

### Dart의 단점

#### 1) Dart 를 쓰는 곳이 Flutter 말고는 적습니다.

Swift는 iOS, Kotlin은 Android, JS는 웹 전반… 이런 느낌에 비해  
Dart는 대체로 Flutter 중심이라 **언어 생태계 확장성이 제한적**으로 느껴질 수 있습니다.

#### 2) 패키지 품질 편차가 있습니다.

pub.dev 패키지가 많긴 한데, 인기 없는 패키지는 유지보수가 약하거나 문서가 빈약한 경우도 있습니다.  
(이건 어떤 생태계든 있지만 Flutter/Dart도 체감될 때가 있음)

#### 3) 비동기(Future/Stream)에서 설계가 흔들리면 코드가 금방 복잡해집니다.

특히 초반에 Stream, 상태관리, 이벤트 흐름을 대충 섞으면 디버깅이 어려워질 수 있습니다.

> Dart는 Flutter의 개발 방식(선언형 UI, 빠른 반복, 비동기 처리)에 최적화된 언어로,  
> 개발 속도(Hot Reload)와 배포 성능(AOT)을 동시에 잡는 구조가 강점입니다.  
> 다만 Flutter 외 활용처가 상대적으로 좁고, 비동기/상태 설계를 잘못 잡으면 복잡해질 수 있습니다.
