Astro + MDX 로 글 하나가 파일 하나이고, 커밋하면 Vercel 이 배포하는 구조입니다.

제가 이전에 쓰던 티스토리(`hyuk-todayfeelsogood.tistory.com`)에 있던 글 116개를 옮겨왔습니다.

꽤나 많이 썻네요... 나 좀 열심히 했을지도?

옮기면서 힘들었 던 것들을 정리했습니다.

tistory에서 이미지 404장을 전부 받아왔습니다

그런데 이부분도 AI에게 하니 정말 빠르게 해줬습니다.. ㅎㄷㄷ..

처음에는 티스토리 CDN 주소를 그대로 쓸 생각이었습니다. 이미지가 404장이고 48MB 라, 저장소에 넣는 것보다 링크만 걸어두는 쪽이 가벼우니까요.

그런데 티스토리 이미지 주소는 **서명된 URL** 이었습니다.

```
...?credential=...&expires=...&signature=...
```

`expires` 가 지나면 전부 404 가 됩니다. 그렇다고 뒤의 서명 부분을 떼어내면 그것도 404 입니다.

즉 지금 붙여넣은 주소는 언젠가 반드시 죽습니다. 그게 언제인지만 모릅니다.

그래서 404장을 전부 받아서 `public/images/<주소>/` 에 넣었습니다. 저장소가 48MB 무거워졌지만, 글 116개의 이미지가 어느 날 통째로 깨지는 것보다는 낫다고 봤습니다.

---

티스토리에는 보호글이 있었습니다. 그걸 옮겨오려니 비밀글이 필요했습니다.

처음 떠오른 방법은 간단합니다. 본문을 그려두고 JS 로 가린 다음, 비밀번호가 맞으면 보여주는 겁니다.

페이지 소스를 열면 본문이 그대로 있습니다. 비밀번호를 물어보는 화면만 얹혀 있을 뿐입니다.

정적 사이트라 서버에서 막을 방법이 없습니다. 그러면 남는 선택은 하나뿐이었습니다 — **본문 자체를 암호문으로 내보내는 것**입니다.

빌드할 때 본문 HTML 을 AES-GCM 으로 잠그고, 읽는 사람 브라우저에서 풉니다. 비밀번호에서 키를 뽑는 건 PBKDF2-SHA256 20만 회입니다. 폰에서 푸는 데 0.2\~0.4초쯤 걸립니다.

비밀번호를 모르면 브라우저에도 본문이 없습니다.

재미있었던 건 **비밀번호가 맞는지 확인하는 코드를 따로 안 썼다**는 점입니다. 틀린 키로 풀면 AES-GCM 이 인증 태그에서 걸려 예외를 던집니다. 못 풀면 틀린 겁니다.

여기서 제일 신경 쓴 건 암호가 아니라 **실수했을 때 뭐가 되느냐**였습니다.

비밀번호를 환경변수에 안 넣은 채로 빌드하면, "비밀글"이라고 써놓고 본문은 다 보이는 페이지가 배포됩니다. 그게 제일 나쁜 결과입니다.

그래서 그 경우에는 빌드를 세웁니다.

```ts
if (!password) {
  throw new Error(
    `비밀글 「${postId}」 을 잠글 비밀번호가 없습니다.` + ...
  )
}
```

검색엔진 쪽을 보다가 알았습니다.

글 122개의 meta description 이 전부 같은 문장이었습니다. 사이트 전체 소개문 하나가 모든 글에 복사되고 있었거든요.

옮겨온 글 116개에는 `description` 이 없습니다. 티스토리 원본에 없었으니까요.

방법은 두 가지였습니다. 116개에 소개문을 지어서 채우거나, 본문에서 뽑거나.

임의로 짓지 않고 본문 앞부분에서 155자를 잘라 `<head>` 에만 쓰기로 했습니다.

코드블록·이미지·마크다운 기호를 걷어내고 남은 글자입니다.

중요한 건 **화면에는 여전히 안 보인다**는 것입니다. 목록 카드에서 소개문 줄은 그냥 빠집니다.

소개문이 없는 글은 없는 채로 보이는 게 맞다고 봤습니다.   
검색엔진에 줄 문장이 필요했던 것이지, 카드를 채우고 싶었던 게 아니니까요.

그리고 여기에 함정이 하나 있었습니다.

**비밀글에서는 본문을 뽑으면 안 됩니다.** 본문을 잠가놓고 meta description 으로 앞부분 155자를 흘리면 잠근 의미가 없습니다.

RSS 도 같은 이유로 비밀글을 통째로 뺐습니다. 피드 리더는 비밀번호를 물어봐 주지 않으니까요.

### 폰에서 글을 쓰려다 정말 UI가 최악인 것을 확인.

글은 대부분 폰에서 씁니다. 그래서 Decap CMS 를 붙여 `/admin` 에서 쓰게 했습니다.

Decap 은 데스크톱 기준으로 만들어져 있어서, 폰에 맞추는 데 자잘한 게 계속 나왔습니다.

- 입력칸 글자가 15px 이라 **탭할 때마다 화면이 확대**됐습니다. iOS 사파리는 16px 미만 입력칸을 그렇게 처리합니다.
- 필드 간격이 36px 인데 필드가 열 개라, 폼 한 번 채우는 데 스크롤이 한참이었습니다. 18px 로 줄였습니다.
- 본문 칸이 300px 이라 대여섯 줄 만에 찼습니다. 그때부터는 작은 창 안에서 스크롤하며 글을 쓰게 됩니다. `60vh` 로 늘렸습니다.
- "콘텐 츠", "빠른 추 가"처럼 버튼 글자가 두 줄로 꺾였습니다.

여기까지는 CSS 로 됩니다. 진짜 문제는 본문 편집기였습니다.

Decap 의 마크다운 위젯은 두 가지 모드가 있는데, **폰에서는 양쪽 다 못 씁니다.**

리치 텍스트 모드는 한글 입력이 끊기고 코드펜스를 망칩니다. 그래서 마크다운 원문 모드만 남겼더니, 이번에는 **툴바 버튼이 전부 `disabled` 로 렌더**됩니다. 굵게도 안 되고 사진은 아예 못 넣습니다.

한쪽은 글이 깨지고 다른 쪽은 버튼이 죽어 있습니다. 고를 게 없었습니다.

그래서 위젯을 통째로 갈아끼웠습니다. 마크다운 원문 textarea 에 직접 만든 툴바를 얹었습니다 

— 제목, 굵게, 색, 형광펜, 사진, 코드블록.

**저장되는 건 여전히 마크다운 원문입니다.**   
툴바는 커서 자리에 마크다운을 꽂아 넣기만 합니다. 형식을 바꿨으면 손으로 쓴 글 122개와 갈라졌을 겁니다.

색을 넣는 방식도 한 번 고쳤습니다. 처음에는 색 값을 본문에 박으려다, 그러면 다크·라이트 중 한쪽에서 반드시 안 읽힌다는 걸 깨닫고 클래스만 넣기로 했습니다. 실제 색은 테마별로 CSS 가 고릅니다.

### 되돌리기를 살리려다 띄어쓰기를 잃었습니다

여기서 예상 못 한 버그가 하나 나왔습니다.

툴바가 글자를 넣을 때 `textarea.value` 를 직접 갈아끼우면 브라우저의 실행취소 기록이 끊깁니다. 버튼 한 번 누르면 그 전으로 못 돌아갑니다.

그래서 `document.execCommand('insertText')` 를 씁니다. 이걸 쓰면 ⌘Z 가 살아 있습니다.

그런데 크롬·사파리에는 "똑똑한 교체"라는 게 있습니다. 단어 하나를 통째로 고른 채 무언가를 넣으면 **옆에 붙은 띄어쓰기를 저 혼자 지웁니다.**

단어를 골라 색을 입혔더니 닫는 태그 뒤의 띄어쓰기가 사라졌습니다.

결국 넣은 뒤에 결과를 대조하고, 어긋나면 직접 갈아끼웁니다.

```js
if (!ok || ta.value !== expected) {
  ta.value = expected
}
```

이 경우에만 되돌리기가 끊깁니다. 글자가 틀리는 것보다는 낫다고 봤습니다.

## 붙였다가 되돌린 것

글 상세 화면을 넓은 모니터에서 보면 양옆이 400px 넘게 비어 있었습니다.

그게 아까워서 오른쪽에 프로필·프로젝트·연락처를 붙이고, 글 폭도 832에서 912px 로 넓혀 봤습니다.

만들고 나서 몇 번 읽어보고 **되돌렸습니다.**

읽는 화면에는 글만 있는 편이 나았습니다. 양옆이 비어 보이는 건 낭비가 아니라 여백이었습니다.

이걸 §8 기록에 "같은 제안을 다시 하지 마세요"라고 적어뒀습니다. 다음에 또 넓은 화면을 보면 똑같은 생각을 할 게 뻔하거든요.

되돌린 커밋에 구현이 통째로 남아 있으니, 정말 다시 필요해지면 그때 꺼내면 됩니다.

## 판단의 근거를 파일 하나에 모았습니다

이번 이틀에서 제일 남는 건 코드가 아니라 **`CLAUDE.md` 라는 파일 하나**입니다.

블로그를 고칠 때마다 같은 질문이 반복됐습니다. 색을 어디서 가져오는지, 이미지를 어디에 두는지, 카테고리와 태그를 어떻게 나누는지.

한 번 정한 걸 다음에 또 정하고 있었습니다. 그리고 지난번과 다르게 정할 때도 있었습니다.

그래서 규약을 한 파일에 모았습니다. 말투, frontmatter 규칙, 디자인 토큰, 색 대비 기준, 그리고 **고친 것 기록**입니다.

기록에 뭘 쓰고 뭘 안 쓸지도 규칙으로 정했습니다.

- **코드 설명은 안 씁니다.** 함수 이름과 구현은 파일을 열면 보입니다. 여기 옮겨 적으면 코드가 바뀔 때 같이 썩습니다.
- 대신 **코드만 봐서는 모르는 것**을 씁니다 — 왜 이 방법이었는지, 뭘 안 하기로 했는지, 어디를 건드리면 안 되는지.

앞에 쓴 것들이 전부 그 형태입니다. "이미지를 받아왔다"가 아니라 "서명 URL 이라 언젠가 죽어서 받아왔다"입니다.

전자는 코드에 있고, 후자는 어디에도 없습니다.

이번에 남은 건 두 가지입니다.

**정적 사이트에서는 "가려두기"가 통하지 않습니다.** 서버가 없으니 브라우저에 안 보내거나, 보낸 걸 못 읽게 만들거나 둘 중 하나입니다. 비밀글을 붙이기 전까지는 이 차이를 별로 생각해 본 적이 없었습니다.

**되돌린 작업도 기록해 둘 값어치가 있습니다.** 사이드바를 붙였다 뺀 건 커밋 로그에는 두 줄로 남습니다. 왜 되돌렸는지가 없으면 다음에 또 붙일 겁니다.
