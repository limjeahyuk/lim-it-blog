### **\- event**

전 시간에 했었던 이벤트 리스너를 사용하는 것을 알겠습니다.  
이제 문제는 변경하는 값들로 무엇을 하고 어떻게 가지고 오는지입니다.

![](/images/react-36/1.png)

이런 식으로 타이틀이 변경될 때마다 console 창에 event를 찍어보도록 하겠습니다.

![](/images/react-36/2.png)

title 입력창에 아무 글씨나 썼는 데 뭔가 이상한 것들이 많이 찍혔습니다.  
우리가 자세히 봐야 할 것은 target 부분입니다.

![](/images/react-36/3.png)

event 안에 target에 value에 가보니 1이라는 숫자가 나타나 있습니다.  
이것이 사용자가 입력한 값입니다.

이 부분을 이용해서

![](/images/react-36/4.png)

useState를 사용해서 title 값이 바뀔 때마다 enteredTitle에 값을 저장해줍니다.

### **\- useState 사용법**

![](/images/react-36/5.png)

사용자에게 Title과 Amount, Date를 입력받습니다.

![](/images/react-36/6.png)

이런 식으로 Title , Amount, Date 따로따로 관리해주는 방법이 있습니다.

이 방법으로는 사용할 때도 이름에 맞춰서 사용하면 되기에 확실하고 최신화를 시키지 않아도 괜찮습니다.  
하지만 어마어마하게 많아지면 코드가 좀 복잡해지고 보기 싫어질 수 있습니다.

다른 방법으로는

![](/images/react-36/7.png)

이런식으로 하나의 useState를 사용하고 json 형식으로 데이터를 관리하는 것입니다.

이 방법은 코드가 좀 깔끔하며 사용할 때 setUserInput으로 통일되기에 좀 더 편할 수 있습니다.  
하지만 항상 최신화를 시켜줘야 합니다.  
만약 title 값 하나만 바꿔야 할 때는 Amount와 Date 값을 전에 값으로 최신화시켜주고 title 값을 넣어야 합니다.  
최신화를 시켜주지 않고 title 값 하나만 넣으면 amount, date 값이 다 날아가는 대참사가 일어납니다.

![](/images/react-36/8.png)

이런 식으로 setUserInput을 사용할 때 스프레드 연산자를 이용하여  
전의 값을 다 가져오고 enteredTitle만 값을 넣어주는 형식으로 꼭 사용해야 합니다.

![](/images/react-36/9.png)

이런 식으로 각기 다른 3개의 상태로 접근하는 것이 아닌 하나의 상태로 접근하는 방식을 사용할 때는  
다른 값을 복사해서 잃어버리지 않도록 코딩을 잘해야 합니다.

또한 가장 큰 문제점은 기존 값을 복사하기 위해 이전 state의 스냅샷에 의존하고 새로운 값으로 오버라이드 합니다.

![](/images/react-36/10.png)

하지만 리액트는 상태 업데이트 스케줄을 가지고 있어서 바로 실행하지 않습니다.  
그렇기에 수많은 상태 업데이트를 계획한다면 오래되었거나 잘못된 상태스냅샷에 의존할 수가 있습니다.

![](/images/react-36/11.png)

확실한 스냅샷에 의존하기 위해 함수를 한 번 더 사용함으로써 스냅샷도 최신화를 시켜줍니다.

### **\- Submit**

![](/images/react-36/12.png)

이런 식으로 전부 작성하고 버튼을 누르면 폼이 제출되도록 만들려고 합니다.  
원래는 onClick 리스너를 이용해서 폼 요소들을 전부 가지고 오는 코드를 짜야하지만...  
버튼의 type을 submit으로 했다면 자동으로 폼 요소를 수신할 수 있는 이벤트를 생략합니다.

Submit 이벤트는 Submit에 반응하는 폼에서 폼이 제출될 때마다 일부 함수를 실행합니다.  
그 함수는 우리가 집접 만드는 함수일 것입니다.

하지만 Submit을 이용하면 버튼을 누를 때마다 페이지가 다시 로드됩니다.

우리는 새로고침 하지 않고 버튼을 누르면 값이 콘솔 창에 나오도록 하고 싶습니다.

![](/images/react-36/13.png)

그럴 때 사용하는 것이 event.preventDefault 함수입니다.

이 함수를 사용하면 기본 요청이 보내지는 것을 막기 때문에 페이지에 머물게 됩니다.

expenseDate에 title, amount, date 값을 저장하고 title , amount, date 값을 초기화시켜줍니다.

### **\- 양방향 바인딩**

state를 사용하는 가장 큰 장점 중 하나입니다.

양방향 바인딩은 변경되는 입력값만 수신하는 것이 아니라 입력에 새로운 값을 다시 전달할 수도 있는 것입니다.  
예를 들어 바로 위에 코드에서 title, amount, date의 값을 초기화시켜준다고 했는데...  
이것이 가능한 것은

![](/images/react-36/14.png)

value에 state 값을 넣어주는 것입니다.

이런 식으로 초기화를 시켜주는 것인데 이게 되나? 무한 루프 아닌가? 싶을 수도 있습니다.

상태를 업데이트하기 위해 입력에서 변경사항을 수신하고  
입력에서 상태를 다시 보내줍니다. 그래서 상태를 변경하면 입력도 변합니다.

돌려보면 매우 잘 돌아갑니다.

이것이 양방향 바인딩으로 state의 큰 장점 중 하나입니다.
