### Flutter는 어떤 성격의 프레임워크인가?

> Flutter는 구글이 만든 크로스플랫폼 UI 프레임워크입니다.

한 번 만든 코드(주로 Dart)를 기반으로 **iOS/Android(그리고 Web/데스크톱까지)**에서 동일한 UI와 동작을 구현하는 걸 목표로 합니다.

> one Source mutle use  

Flutter의 핵심은 **각 플랫폼의 기본 UI 컴포넌트를 호출해서 조립**하는 방식이 아니라,  

**Flutter가 직접 화면을 그려서(Rendering)** 앱 UI를 만든다는 점입니다.

그래서 플랫폼이 달라도 UI 일관성이 높고, 애니메이션/커스텀 UI에 강합니다.

* * *

### Flutter의 핵심 특징

#### 1) 위젯 중심 UI

Flutter에서 화면은 전부 **위젯의 트리 구조**로 표현됩니다.  
텍스트, 버튼, 패딩, 정렬, 애니메이션까지 전부 위젯입니다.

-   장점: UI를 조립하듯 구성 가능, 재사용성이 좋음
-   단점: 처음에는 코드가 길어 보이고(트리 중첩), 구조를 못 잡으면 복잡해짐

#### 2) 자체 렌더링 엔진 기반 (플랫폼 의존 UI가 낮음)

플랫폼 기본 버튼을 그대로 가져다 쓰는 방식이 아니라,  
Flutter가 자체적으로 픽셀을 그려 UI를 만든다.

-   장점: iOS/Android 간 UI 일관성 좋음, 커스텀 UI/애니메이션 강함
-   단점: 플랫폼 기본 느낌을 완벽하게 따르려면 별도 조정이 필요할 수 있음

#### 3) Hot Reload / 빠른 개발 사이클

UI 개발할 때 수정 → 즉시 반영이 매우 빠르다.

-   장점: UI 반복 작업, 프로토타이핑, 디자인 수정에 매우 유리
-   단점: 구조/상태관리를 대충 시작하면 나중에 리팩토링 비용이 커질 수 있음

#### 4) 하나의 언어(Dart)로 앱 전반을 개발

UI뿐 아니라 상태관리, 비즈니스 로직까지 Dart로 진행한다.

-   장점: 팀 생산성(특히 멀티플랫폼), 코드 공유 극대화
-   단점: iOS/Android 네이티브 지식이 필요 없는 건 아님(플러그인/브릿지/권한/빌드 이슈 등)

* * *

### Flutter의 장점

#### 1) 한 번 개발 → 여러 플랫폼 생산성

같은 기능을 iOS/Android 각각 따로 만들 필요가 줄어듭니다.  
특히 **UI가 많이 겹치고, 출시 속도가 중요한 서비스**에 강력합니다.

#### 2) UI/애니메이션 구현이 강함

커스텀 UI, 부드러운 애니메이션, 브랜드 디자인을 살린 인터랙션을 구현하기 좋습니다.

#### 3) 일관된 UI/동작

플랫폼이 달라도 동일한 UI를 유지하기 쉬워서 QA/디자인 관리가 편해집니다.

#### 4) 생태계(패키지)와 커뮤니티가 큼

대부분의 기능(네트워크, 상태관리, 라우팅, Firebase 등)은 이미 패키지로 잘 제공됩니다.

* * *

### Flutter의 단점 / 주의할 점

#### 1) “완전한 네이티브 대체”는 아님

카메라/푸시/블루투스/위젯/워치/백그라운드 등  
**플랫폼 의존 기능**은 결국 네이티브 영역을 건드리게 될 수 있습니다.

-   플러그인이 있으면 해결되지만
-   없거나, 요구사항이 특수하면 직접 네이티브 코드(iOS/Android)를 붙여야 합니다.

#### 2) 앱 용량 증가 가능성

렌더링 엔진/리소스 등으로 인해 아주 작은 앱은 네이티브 대비 용량이 커질 수 있습니다.  
(다만 요즘은 최적화가 많이 되어, 프로젝트 성격에 따라 체감이 달라짐)

#### 3) 플랫폼 고유 UX를 그대로 따라가려면 추가 작업

Flutter UI는 일관성은 좋지만,  
반대로 말하면 iOS/Android 각 플랫폼 특유의 디테일을 100% 맞추려면 손이 더 갈 수 있습니다.

#### 4) 상태관리/아키텍처 선택이 초기 난이도

Flutter는 자유도가 높은 만큼, 초반에 구조를 잘못 잡으면 코드가 쉽게 엉킬 수 있습니다.  
(이건 React/SwiftUI도 비슷하지만, Flutter도 “상태관리 선택”이 중요)

* * *

### Flutter가 특히 잘 맞는 상황

-   **iOS/Android 동시 출시가 필수**이고 개발 인력이 제한적일 때
-   UI가 중요하고, 디자인 변경/실험이 잦은 서비스(프로토타이핑, 빠른 iteration)
-   스타트업/신규 서비스처럼 **속도와 비용**이 중요한 경우
-   기능이 **일반적인 모바일 앱 범주**에 속하는 경우(로그인, 리스트, 결제, 지도, 푸시 등)

* * *

> Flutter는 하나의 코드로 여러 플랫폼을 빠르게 개발하면서도,  
> UI/애니메이션을 강력하게 커스텀할 수 있는 프레임워크입니다.  
> 다만 플랫폼 의존 기능/빌드/브릿지 영역에서는 네이티브 지식이 필요할 수 있고,  
> 초기 구조(상태관리/아키텍처)를 잘 잡는 것이 중요합니다.
