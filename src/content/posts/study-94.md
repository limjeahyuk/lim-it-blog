### **한줄 요약**

> PNG  
> → 손실 없이 깔끔한 이미지, 투명 배경 지원, 무손실 압축 = 용량이 큼  
>   
> JPG  
> → 사진을 작게 압축하는 데 최적화, 약간의 품질이 깨질 수 있지만 파일이 훨씬 작음

PNG는 다들 사진을 저장할 때 뒷배경이 투명하다는 것을 인지 하고 있을 것입니다.

그 때 사용을 하는 것이고 JPG는 그냥 사진 같은 경우 대체로 많이들 사용하고 있습니다.

* * *

#### **PNG (Portable Network Graphics)**

손실 없는 데이터 압축을 지원하는 래스터 그래픽스 파일 형식입니다.

PNG는 GIF의 개선된, 특허 없는 대체 형식으로 개발 되었습니다.

**특징**

\- 무손실 압축

저장했다가 열어도 원본 데이터가 그대로 유지됩니다.

\- 투명도 지원

아이콘, 로고 처럼 배경이 투명해야할 때 필수.

\- 단색 / 선명한 도형, 텍스트가 많은 이미지에 최적입니다.

#### **JPG (Joint Photographic Experts Group)**

디지털 이미지 특히 디지털 사진으로 생성된 이미지에 일반적으로 사용되는 손실 압축 방식입니다.

**특징**

\- 손실 압축

\- 사진 풍경 인물처럼 색과 디테일이 복잡한 이미지에 최적

여러 번 재저장하면 품질이 점점 망가질 수 있습니다.

#### **용도/상황별 추천**

**사진(인물, 풍경, 음식, 일상샷)**

-   **JPG 추천**
    -   블로그 글에 많이 올리는 사진: JPG로 70~85 정도 품질로 저장하면 용량과 품질 균형 좋음.
    -   너무 고품질(100%)로 저장하면 용량만 커지고, 체감 품질 차이는 크지 않은 경우가 많음.

**스크린샷, 앱 화면 캡처, 코드 캡처**

-   **PNG 추천**
    -   텍스트 선명도 중요
    -   색 번짐 없이 픽셀이 깔끔하게 유지
    -   macOS/iOS 기본 스크린샷도 보통 PNG인 이유가 이거

**로고, 아이콘, 버튼, UI 리소스**

-   **투명 배경 필요 → 무조건 PNG**
-   배경색과 상관없이 자연스럽게 올려야 할 때 PNG가 필수

**썸네일, 카드형 미리보기 이미지**

-   대부분 **JPG** 사용
    -   사진 느낌이 대부분이라서
    -   썸네일은 한 페이지에 여러 개 뜨니 용량 중요

**일러스트 / 웹툰 / 픽셀아트**

-   선명함이 중요하고, 색상 경계가 명확한 경우가 많기 때문에  
    → **PNG가 더 적합**
-   다만 웹 최적화를 위해, 경우에 따라 JPG로도 쓰지만 디테일이 조금 희생될 수 있음.

* * *

#### **성능 / 최적화 관점**

1.  **페이지 로딩 속도**
    -   JPG가 같은 해상도에서 대체로 훨씬 가볍습니다.
    -   특히 **배경 사진 + 여러 썸네일**처럼 이미지가 많은 페이지에서는 JPG 비중을 높이는 게 좋습니다.
2.  **LCP, CLS 같은 웹 성능 지표**
    -   큰 이미지(히어로, 썸네일)를 JPG로,
    -   작은 UI 요소(아이콘, 로고)를 PNG로 두면
    -   로딩 속도와 시각적 선명도를 둘 다 챙길 수 있습니다.
3.  **반응형 이미지(<img srcset> 등)**
    -   JPG는 해상도별로 여러 버전을 제공하기 좋습니다.
    -   PNG는 애초에 사이즈가 크니까, 정말 필요한 UI 요소에만 사용 → 나머지는 JPG + WebP 같은 조합이 효율적.

* * *

#### **간단 정리**

PNG로 해야 하는 경우

-   배경이 투명해야 한다.
-   아이콘/로고/버튼 등 UI 요소다.
-   텍스트/선/도형이 많은 이미지이고 흐릿해지면 안 된다.
-   여러 번 열고 저장해도 품질이 그대로 유지돼야 한다.

JPG로 해야 하는 경우

-   사진(인물, 풍경, 음식 등)이다.
-   용량을 최대한 줄여야 한다.
-   큰 배너/배경 이미지라 유저가 자주 다운받거나 볼 것이다.
-   썸네일, 리스트 카드 이미지 등 한 화면에 여러 장 띄워야 한다.
