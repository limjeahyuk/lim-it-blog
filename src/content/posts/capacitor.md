## Ionic Capacitor

웹 기술 ( HTML, CSS, JavaScript )로 만든 웹 애플리케이션을 iOS, AOS 로 쉽게 변환해주는 오픈 소스 크로스 플랫폼 입니다.

기존의 Cordova를 대체하기 위해 개발을 했다고 합니다.

<img src="https://res.cloudinary.com/m1zcmsux/image/upload/c_limit,f_auto,q_auto,w_1600/v1790138897/q1dzyylveinkyxaq6fxs.png" alt="설명" width="268">



요즘에는 웹으로 안되는 게 거의 없습니다. 너무 쉽게 만들수도 있고 엄청나게 많은 기술들이 있으며...

웹에서 만들어서 어디서든 호환이 가능하고 모바일의 기능도 쉽게 사용을 할 수 있습니다.

그렇기 때문에 요즘 하이브리드형 앱이 많아졌다를 넘어서 거의 모든 앱이 하이브리드인 것 같기도 합니다..



저 또한 개발을 할 때, 주로 웹으로 먼저 만들게 됩니다.

아무래도 접근성이 쉽고 그리고 테스트도 그냥 쉽게 가능하니까??

그 이후에 괜찮으면 앱으로 묶어볼까? 라는 생각이 들 게 됩니다.



이때 iOS만 해야지\~ 라고 생각하기에는 약간 아쉬운게 있습니다.

AOS는...? 그래서 제가 공부한건 Flutter인데.. 근데 또 굳이 webView 하나만 띄우는건데 Flutter를 써야하나?



이때 사용하는 것이 **Capacitor** 입니다.

---

### 작동원리

Capacitor의 핵심은 웹 앱을 네이티브 기기의 WebView(웹뷰)라는 보이지 않는 브라우저 창 안에 띄우는 것입니다. 

하지만 단순한 웹사이트를 보여주는 것을 넘어, 네이티브 기능과 웹 앱을 이어주는 Bridge 역할을 합니다.



- **웹 코드**
  - React, Vue, Angular 또는 바닐라 자바스크립트 등 여러 최신 웹 프레임워크로 UI와 비즈니스 로직을 작성합니다.
- **Capacitor Bridge**
  - 웹 뷰 안의 자바스크립트 코드와 스마트폰의 네이티브 운영체제(iOS/Android) 사이에서 메시지를 주고받습니다.
- **플러그인** 
  - 카메라, GPS, 파일 시스템, 푸시 알림 등 스마트폰의 하드웨어 기능에 접근해야 할 때,   
  자바스크립트 API를 호출하면 플러그인이 이를 네이티브 코드(Swift/Kotlin)로 변환해 실행합니다.

---

### 주요 장점

- **완벽한 크로스 플랫폼**
  - 코드 한 번 작성으로 iOS, AOS 앱은 물론 브라우저에서 실행되는 PWA 까지 동시에 배포할 수 있습니다.
- 최신 웹 기술 호환성
  - 과거 프레임워크와 달리 npm 기반의 최신 자바스크립트 생태계와 완벽히 호환됩니다.  
  특정 프레임워크에 종속되지 않습니다.
- 1급 네이티브 접근성
  - 네이티브 프로젝트를 소스컨트롤에 직접 포함 시킵니다.  
  원한다면 언제든 Swift나 Kotlin 코드를 직접 수정하거나 추가할 수 있습니다.
- 수월한 플러그인 생태계
  - Capacitor 공식 플러그인 뿐만 아니라, 방대한 기존 Cordova 플러그인들도 대부분 그대로 가져다 사용할 수 있어서 확장성이 뛰어납니다.

### 궁금한 점



iOS에서는 비행기모드일 때 앱을 열었을 때 아무 동작도 하지 않으면 반려를 당합니다.

제가 처음 이걸 모르고 WKWebView만 띄워서 url만 바꿔서 웹을 쉽게쉽게 앱으로 테스트 할수 있지 않을까 싶어서 만들어봤었습니다. 이때 바로 반려를 당했던 기억이 있습니다.

이처럼 Capacitor도 사실 위와 동일한 앱이지 않을까 싶었습니다. 그래서 iOS에서 반려 당하는거 아니야? 싶은 생각이 들었습니다.



> 웹뷰만 있는 앱을 App Store에서 반려한다는 것은 **정확한 사실**입니다. 



오프라인 상태에서 앱을 켰을 때 아무것도 없는 하얀 캔버스나 브라우저 에러 창이 뜨면 앱스토어 심사(Guideline 4.2 - 최소한의 기능)에서 탈락합니다.

하지만 이 문제 때문에 Capacitor를 사용하지 못하는 것은 **절대 아닙니다.** 



Capacitor는 이 기준을 통과할 수 있도록 설계되어 있습니다.

#### 1. 리모트 URL 방식 vs 로컬 번들링 방식 (Capacitor)

애플이 반려하는 이른바 단순 웹뷰 앱은 앱을 켜자마자 외부 웹사이트 주소를 불러오도록 만든 앱입니다. 

인터넷이 끊기면 웹 서버에 접속할 수 없으니 브라우저 에러 화면이 뜰 수밖에 없습니다.



반면, **Capacitor는 로컬 번들링방식을 사용합니다.**

- `npm run build`를 하고 `npx cap sync`를 실행하면, 완성된 HTML, CSS, JavaScript 파일들이 스마트폰 앱 설치 파일 내부에 **물리적으로 복사**됩니다.
- Capacitor 앱은 인터넷에 있는 웹페이지를 띄우는 것이 아니라, **스마트폰 기기 안에 다운로드되어 있는 HTML/JS 파일을 불러와서 화면을 그립니다.**
- 따라서 비행기 모드나 와이파이가 없는 오프라인 상태에서 앱을 켜도 앱의 뼈대(UI), 로고, 하단 탭 메뉴 등은 인터넷 연결과 무관하게 즉시 화면에 나타납니다.

#### 2. 개발자가 추가로 대비해야 할 점

Capacitor가 오프라인에서도 화면을 정상적으로 띄워주긴 하지만, 심사를 한 번에 통과하려면 개발자가 React 코드 단에서 약간의 대비를 해주어야 합니다.

앱의 화면은 켜지더라도 서버에서 데이터를 가져오는 API 호출(게시글 목록 불러오기, 로그인 등)은 인터넷이 없으면 실패하게 됩니다. 

이때 화면이 멈춘 것처럼 보이게 두어서는 안 됩니다.



- **네트워크 상태 감지**
  - Capacitor가 기본으로 제공하는 `@capacitor/network` 플러그인을 사용하여 사용자의 기기가 현재 오프라인 상태인지 즉시 감지할 수 있습니다.
- **안내 화면 및 UI 처리**
  - 인터넷이 끊겼을 때 빈 화면이나 무한 로딩 바를 띄우지 말고,   
  인터넷 연결 상태를 확인해 주세요라는 친절한 안내 화면이나 팝업을 띄워주어야 합니다.



애플이 싫어하는 것은 '웹 기술을 쓴 앱'이 아니라 '인터넷이 끊겼을 때 먹통이 되어 사용자 경험을 망치는 앱'입니다. 

Capacitor는 로컬에 코드를 탑재하여 기본 화면을 띄워주므로, 네트워크 단절 시 에러 메시지 처리만 잘 해두면 애플 앱스토어 심사를 무난하게 통과할 수 있습니다. 

실제로 수많은 Capacitor 앱들이 현재 앱스토어에 등록되어 서비스 중이라고 합니다.

### 실제 React 앱으로 빌드하는 방법



1. React 프로젝트 빌드

```
npm run build
```

Capacitor는 완성된 웹 파일들을 웹뷰 안에 넣는 방식이므로, 먼저 React앱을 빌드해야합니다.

Vite 기반 프로젝트라면 보통 dist 폴더가, CRA 기반이라면 build 폴더가 생성됩니다.



2. Capacitor 패키지 설치

```
npm install @capacitor/core
npm install -D @capacitor/cli
```

프로젝트에 Capacitor 핵심 라이브러리와 터미널에서 사용할 CLI 도구를 설치합니다.



3. Capacitor 초기화

```
npx cap init
```

프로젝트에 Capacitor 설정 파일을 생성합니다.



이 명령어를 실행하면 터미널에서 두가지를 물어봅니다.



1. App name: 앱의 이름 (예: `My React App`)
2. App Package ID: 앱의 고유 식별자 (예: `com.mycompany.myapp`)



초기화가 끝나면 `capacitor.config.ts` (또는 `.json`) 파일이 생성됩니다. 

이 파일을 열어 `webDir` 속성이 1단계에서 생성된 빌드 폴더명(`build` 또는 `dist`)과 정확히 일치하는지 확인하고 수정해 주세요.



4. 네이티브 플랫폼 패키지 설치 및 추가

```
# 플랫폼 패키지 설치
npm install @capacitor/android @capacitor/ios

# 프로젝트에 플랫폼 폴더 추가
npx cap add android
npx cap add ios
```

앱으로 만들고자 하는 운영체제의 패키지를 설치하고, 프로젝트에 해당 플랫폼을 추가합니다.

이 단계가 끝나면 프로젝트 루트에 android와 ios라는 폴더가 생성됩니다.



5. 웹 코드 동기화

```
npx cap sync
```

빌드된 React 웹 코드를 생성된 네이티브 플랫폼 폴더 안으로 복사하는 과정입니다.

앞으로 React 코드를 수정하고 다시 빌드 할 때마다 반드시 이 명령어를 실행해야 앱에 반영됩니다.



6. 네이티브 IDE에서 앱 열기 및 실행

```
# 안드로이드 스튜디오 열기
npx cap open android

# 엑스코드 열기 (Mac 전용)
npx cap open ios
```

코드를 안드로이드 스튜디오나 xcode에서 열어 시뮬을 돌리거나 실기기에서 설치해서 실행해볼 수 있습니다.
