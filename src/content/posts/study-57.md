**React와 Nextjs는 기본적으로 같은 REACT 입니다.**

그래서 기본적으로 nextjs는 react에서 사용하던 기능은 다 사용 가능합니다,

그럼 뭐가 다른 것인가?  
Nextjs에서는 React에서 하나하나 설정 해주던 것이 기본적으로 설정 되어 있습니다.

그 정도의 차이점이라고 볼 수 있습니다.

그럼 뭐가 설정 되어 있나?  
가장 큰 것 3가지를 보게 되면

1.  서버측 렌더링 지원
2.  파일 기반 라우팅
3.  풀스택 프레임 워크

이 3가지 정도라고 볼 수 있습니다.

* * *

#### 1\. 서버측 렌더링 지원

React와 Next의 가장 큰 차이점 입니다.

페이지가 렌더링 되는 곳이 차이가 있습니다.

먼저 React의 경우 기본적으로 클라이언트에서 렌더링 한다고 배웠습니다.  
React로만 짜여진 페이지의 소스코드를 보게 되면 상당히 비어있습니다.

![](/images/study-57/1.png)

기본적인 html 뼈대와 id="root"부분에만 react앱이 로딩되고 렌더링 되어 있습니다.  
이처럼 렌더링이 모두 클라이언트 쪽에서 처리가 된다는 것입니다.

이렇게 되었을 때 문제는 만약 서버에서 데이터를 가져와서 사용자에게 보여줘야하는 경우에는  
즉 요청이 전송될 때 잠깐 동안 페이지가 깜빡이는 로딩 상태를 보게 됩니다.

왜냐하면 클라이언트 측에서 js 코드가 실행된 뒤에 데이터를 가져오기 때문입니다,  
전송된 요청의 회신을 대기하느라 로딩이 생기게 됩니다.

반대로 next로 만든 페이지는

![](/images/study-57/2.png)

뭐가 엄청 많습니다... react 페이지와는 다르게 h1 태그도 보이고 a태그도 보입니다.

이것이 **서버에서 렌더링을 먼저 해서 보내준다는 것입니다.**

데이터를 서버에서 조회를 해서 페이지를 꾸려야할 때 Next의 경우  
서버에서 해당 페이지를 사전 렌더링 한 상태에서 서버에 요청이 들어왔을 때 해당 데이터를 서버에서 가져오면  
완성된 페이지가 사용자에게 제공됩니다.

이렇게 되면 사용자는 깜빡이는 로딩 상태를 보지 않아도 됩니다.

* * *

#### **2\. 파일 기반 라우팅**

기본적으로 React에서는 라우터가 없었습니다.

※ 라우터란 사용자에게 여러 페이지가 있는 것처럼 보이게 하는 것입니다.   
url의 이동으로 다른 페이지가 보이도록 합니다.

React에서 라우트를 사용하려면 React 라우터라는 패키지를 받아서 사용해야 했습니다.  
패키지를 받고 페이지마다 하나하나 설정을 해줬어야 했습니다.

![](/images/study-57/3.png)

반면에  
Next는 그러한 것들을 전부 없앴습니다.  
그대신 파일과 폴더를 이용해서 페이지와 라우트를 정의 했습니다.

옆에 보이는 것처럼 Next를 이용해서 프로젝트를 만들게 되면  
pages 폴더가 있습니다.

pages를 필두로 그 밑에 advertise 폴더의 support라면  
/advertise/support 이런식으로 자동으로 설정 됩니다.

이런식으로 **React에서 하나하나 설정 해줘야 했던 것 들이**  
**Next에서는 자동으로 설정이 됩니다.**

* * *

#### **3\. 풀스택 프레임워크**

Nextjs는 풀스택 프레임 워크입니다.

풀스택 프레임워크란 개발자가 React 프로젝트에 백엔드 코드를 쉽게 추가할 수 있다는 것입니다.

풀스택 React 프로젝트를 구축하려면 client 코드만 있어서는 안됩니다.  
기본적으로 서버 사이드 렌더링을 하기 위해선 서버 코드도 반드시 필요합니다.  
파일 시스템에서 작업한다거나 데이터베이스에 접근할 수 있어야 합니다.

**Nextjs를 이용하면 한개의 프로젝트로 client 쪽 코드와 백엔드 코드 모두 구축 할 수 있습니다.**
